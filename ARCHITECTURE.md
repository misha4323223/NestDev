# Архитектура: где что лежит

Файл отвечает на два вопроса: **что где живёт** и **как добавлять новое, ничего не забыв**.
Карта интерфейса ниже не декоративная: её проверяет `test/repo-shape.test.js` (тест
«раскладка интерфейса»). Забыли строку, тег в разметке или файл в списке для телефона —
тест падает, а не молчит.

## Слои

| Слой | Файлы | Роль |
|---|---|---|
| Точка входа главного процесса | `src/bootstrap.js` → `src/main.js` | окно Electron, IPC, инструменты агента |
| Мост в окно | `src/preload.js` | превращает IPC в `window.api` для окна |
| Окно (рендерер) | `src/renderer/*` | интерфейс: чат, панели, настройки |
| Сервисы главного процесса | остальные `src/*.js` | git, облако, деплой, почта, хранилища |
| Телефон | `src/mobile-bridge.js` | отдаёт те же файлы окна по LAN; список выдачи — `STATIC_FILES` там же |

Порядок загрузки скриптов окна задаёт `src/renderer/index.html`. Модули, от которых
зависит другой модуль, стоят **до** него: `provider-*.js` и данные ядра — до `agent-core.js`,
`agent-core.js` и панели — до `app.js`.

## Карта интерфейса

Третий столбец — «где это подключается»: `файл: фрагмент`, причём фрагмент обязан
реально быть в этом файле (тест это проверяет). `—` означает «никто не зовёт напрямую».

## Правила

### 1. Новый модуль окна (четыре шага, все обязательны)

1. Файл в `src/renderer/`, разметка подключения — по образцу `provider-transport.js`:
   фабрика `root.Xxx = factory`, зависимости приходят аргументами, наружу — только то,
   что реально нужно.
2. Тег `<script>` в `index.html` **до** того модуля, который его зовёт.
3. Имя файла в `STATIC_FILES` моста (`src/mobile-bridge.js`) — иначе телефон получит 404
   и раздел на телефоне молча перестанет работать.
4. Строка в карте выше. Всё это проверяет `repo-shape` (раскладка интерфейса).

### 2. Вынос куска из большого файла (процесс, он же чек-лист приёмки)

1. **Анализ до правки**: точные границы (якоря), зависимости внутрь и наружу, цена в тестах.
2. Перенос **скриптом с проверкой якорей**: скрипт падает до записи, если якорь не совпал.
3. Текст переезжает **байт в байт**; меняется только доступ к общим данным
   (например, `settings.x` → `getSettings().x`, если модуль живёт дольше одной загрузки).
   **Вызовы в оболочке только ПЕРЕИМЕНОВЫВАЮТСЯ**: `scrollBottom()` →
   `ChatFeed.scrollBottom()`. Подмена вызова другим (даже похожим) — это изменение
   поведения, и оно идёт отдельным решением, а не по ходу выноса. Один такой случай
   уже был ценой пустого чата: `pinnedToBottom = true; scrollBottom();` заменили на
   `ChatFeed.jumpToBottom()`, который дополнительно трогал кнопку «↓» внутри ленты.
4. Перенос **проверяется аудитом**: `bun run audit:extract <до> <после> <модули...>`
   раскладывает ушедшие из оболочки строки на «перенесено как есть», «переименование
   вызова» и «требует глаз»; последние объясняются вручную. Каждая замена нескольких
   строк одним вызовом (например `ensureWorkGroup(); body.appendChild(el)` →
   `ChatWork.addRow(el)`) должна быть сверена по коду модуля.
5. Один этап = один заход, `npm test` целиком зелёный после него.
6. Живая проверка: HTTP моста + запуск скриптов в окне в порядке тегов (в песочнице) и
   `bun run test:live` на ПК. Отдельно — живой прогон **через окно** (ввод → «Отправить»):
   прежние наборы водили работу через `window.api` и потому не видели поломок ленты.
7. OTA пересобран, файлы бандла сверены с диском, версия поднята, заметка в `AGENT-NOTES.md`.

### 3. Как тесты читают текст интерфейса

- `uiFile("app.js")` — конкретный файл; `uiAll()` — весь интерфейс; `uiFind("маркер")` /
  `uiFind("маркер", "конец")` — кусок кода, где бы он ни лежал (после выноса тест не падает).
- **Маркер конца выбирайте внутри самого куска.** Если кусок уехал в модуль, а маркер
  конца остался в `app.js` (например это комментарий *следующей* секции), `uiFind` не
  угадывает — он падает и называет файл и маркер. При выносе это правится одной строкой:
  конец сужается до строки, которая гарантированно уезжает вместе с куском.
- Кто проверяет, что в `app.js` чего-то **больше нет**, читает `app.js` напрямую — это нарочно.
  Но проверка «функция X есть в `app.js`» при выносе X в модуль должна смотреть в модуль
  (или в `uiAll()`): тест падает громко и называет, что именно править.
- Прямых чтений `app.js` в тестах ограниченное число, и оно не должно расти
  (тест «бюджет прямых чтений app.js»; сейчас 33).

### 4. Признаки, что из `app.js` пора выносить

Файл больше 1500 строк, или в нём появилась новая панель, или кусок зовёт наружу больше
десяти имён. Порядок выноса — по возрастанию связности, а не по размеру: сначала то,
у чего на входе 5–10 зависимостей (как `yc-panel.js`), в конце — то, на чём висит весь чат.

### 5. Обновления (OTA): две шкалы версий

- **Версия приложения** (`package.json`) — версия кода. **Номер набора** (`ota/manifest.json`)
  — версия сборки. Это разные шкалы: набор 1.5.125 может быть собран из кода 1.5.114.
- Набор несёт версию кода внутри себя (`manifest.codeVersion`, при применении —
  `version.json`), и приложение решает, грузить ли применённый набор, **по версии кода**:
  набор старше кода в папке — не перекрывает его и удаляется. Судить по номеру набора
  нельзя: номера уходят вперёд, и после `git pull` приложение продолжало запускать старый
  код (ровно жалоба «обновил папку, а версия та же»).
- Поэтому **после обновления кода номер набора должен быть не ниже версии приложения**, а
  лучше — равен ей (`node scripts/make-ota.js --version <версия>`). Панель Self-update
  показывает версию кода и номер набора раздельно, а также все источники и доступное
  обновление — по ней всегда видно, что именно исполняется.
