# Yandex Cloud (yc-инструменты)

Справочник агента. Читается вручную: `agentGuide { name: "yc" }` (или `readFile { path: "agent-guide:yc" }`).
Подключается автоматически, когда в задаче появляется облако (группа `cloud`).

## Порядок работы

1. `ycStatus` — ВСЕГДА начинай отсюда: авторизован ли пользователь (Настройки → «☁️ Yandex Cloud»),
   какой каталог выбран, какие разрешения выданы агенту, счётчики ресурсов по всем сервисам.
2. `ycList` — список ресурсов. `service` — ключ сервиса; без `service` — сводка по всем.
   Возвращает имена и `id`. Результат любой операции проверяй `ycList`, а не по памяти.
3. Создание/удаление/деплой — только по ЯВНОЙ просьбе пользователя и при включённых чекбоксах
   разрешений: ресурсы платные, удаление необратимо.

## Инструменты

- `ycCreate { service, name }` — создание ресурса в выбранном каталоге. `name` — латиница, цифры, дефис.
  Создание доступно для: `ydb`, `lockbox`, `containerRegistry`, `storage`, `dns`, `serverlessContainers`, `vpc`.
- `ycDelete { service, id }` — удаление по `id` (виден в `ycList`). Необратимо и может удалить данные.
- `ycDeploy { directory, name, public }` — деплой папки проекта в Serverless Containers: собирает Docker-образ
  (или генерирует Dockerfile по типу проекта), загружает в Container Registry, создаёт/обновляет
  Serverless Container, при `public: true` настраивает публичный доступ → возвращает URL.
  Требует Docker на ПК и разрешение на создание ресурсов. Деплой платный.
- `ycSecret { action, secret, entries }` — секреты Lockbox. `list` — секреты каталога; `versions` — версии секрета
  (id, дата и ИМЕНА ключей: значения API не отдаёт никогда); `putversion` — новая версия со значениями
  (`entries: { "API_KEY": "…" }`, можно списком `[{ key, value }]`). `putversion` — это создание: нужно разрешение
  «Разрешить агенту создавать ресурсы» и явная просьба пользователя. **Секрет без версии бесполезен**: ревизия
  ссылается на ключ, которого нет. Порядок: `ycCreate { service: "lockbox", name: "app-env" }` → `ycSecret { action: "putversion" }`
  → `ycContainer { action: "deploy", secrets: [{ id, key, environmentVariable }] }`. Значения секретов не повторяй в ответе
  и не вставляй в файлы — они живут только в облаке.
- `ycDns { action, zone, name, type, value, ttl }` — записи DNS-зоны Cloud DNS. `records` — что уже есть,
  `add` — поставить значения для пары «имя+тип» (есть — заменит, нет — добавит), `delete` — убрать все значения
  пары. `zone` — имя или id зоны; без него работает, только если зона в каталоге одна. **Имя зоны при создании —
  домен БЕЗ точки** (`ycCreate { service: "dns", name: "example.com" }`), **имя записи — FQDN С точкой**:
  `www.example.com.`, а вершина зоны — само её имя `example.com.`. Тип: A, AAAA, CNAME, TXT, MX, NS, SRV;
  значение — строка или массив (для MX: `10 mx.example.com.`). `add` требует разрешения «создавать ресурсы»,
  `delete` — «удалять ресурсы». Обновление DNS в интернете расходится от минуты до часов — не жди мгновенной
  проверки через `checkUrl`, но сам адрес деплоя проверь.
- `ycRegistry { action, registry, image }` — образы Container Registry. `images` — что лежит в реестре
  (имя, теги, размер, `id`), `delete` — удалить образ **вместе со всеми его тегами** (необратимо).
  `registry` — имя или id реестра; без него работает, только если реестр в каталоге один. `image` — `id` образа
  (виден в `images`) или его тег. Чистить реестр нужно: каждая выкатка оставляет образ навсегда и он занимает
  платное хранилище. Но перед удалением спроси пользователя и не удаляй тег, на который ссылается работающий
  контейнер — после этого выкатка не соберётся (проверить, что работает: `ycContainer { action: "overview" }`).
  `delete` требует разрешения «удалять ресурсы». Удаление забирает теги: отдельно снять один тег инструмент
  не умеет — для этого нужна консоль облака.
- `ycStorage { action, bucket, key, file, content, prefix }` — файлы в бакете Object Storage. `list` — что лежит
  (можно `prefix` — «папка»), `upload` — положить файл (`file` — путь от рабочей папки) или готовый текст
  (`content`), `download` — забрать объект к себе (`to` — куда, по умолчанию имя объекта в рабочей папке),
  `delete` — убрать объект, `public` / `private` — открыть бакет для чтения из интернета и закрыть обратно.
  `bucket` — имя или id бакета; без него работает, только если бакет в каталоге один
  (создать: `ycCreate { service: "storage", name: "my-site" }`). `upload` требует разрешения «создавать ресурсы»,
  `delete` — «удалять ресурсы», `public` / `private` — «Разрешить агенту делать бакет публичным». Копирование
  файлов в бакете — не перенос, а загрузка. Тип содержимого ставится по расширению ключа: от него зависит,
  откроется картинка в браузере или скачается файл. **Открытый адрес объекта работает у других, только если у
  бакета включён публичный доступ на чтение** — иначе ссылка вернёт отказ; включить его можешь и ты, действием
  `public`. **Правило для `public`:** файлы бакета станет читать кто угодно из интернета, кто знает ссылку, и
  содержимое будет видно ПОИСКОВИКАМ, а не только людям с твоим доступом. Поэтому зови его только по ЯВНОЙ
  просьбе пользователя и не открывай так бакет с паролями, ключами и личными файлами — закрытые данные лежат
  в Lockbox (`ycSecret`). Публичность выключается обратно тем же инструментом (`private`), а из карточки бакета
  в панели «☁️ Cloud» — кнопкой.
- `ycDb { action, database, table, keys, item, key, limit }` — таблицы и записи ДОКУМЕНТНОЙ базы YDB
  (`ycCreate { service: "ydb", name: "app-db" }`, дальше работать с ней было нечем). `tables` — список таблиц,
  `create` — создать (`table`, `keys` — поля ключа, первый HASH, например `{ "id": "S" }`),
  `describe` — структура и число записей, `put` — положить запись (`item` — пары «поле → значение»,
  поля ключа обязательны), `get` — одна запись по `key`, `scan` — показать записи (`limit` до 100),
  `delete` — убрать запись по `key`, `drop` — удалить таблицу ВМЕСТЕ с записями (необратимо).
  `database` — имя или id базы; без него работает, только если база в каталоге одна. Значения полей
  передаются обычным JSON (строка, число, флаг, массив, объект) — типы API ставит сам.
  `create` и `put` требуют «Разрешить агенту создавать ресурсы», `delete` и `drop` — «…удалять ресурсы».
  Это только ДОКУМЕНТНЫЕ таблицы (Document API, DynamoDB-совместимые): обычные SQL-таблицы YQL этот интерфейс не обслуживает.
- `ycMdb { action, engine, cluster, name, version, preset, diskGb, diskType, zone, subnet, user, database, publicIp, minutes, serviceType, limit, confirm }` —
  УПРАВЛЯЕМЫЕ БАЗЫ: Managed Service for PostgreSQL, MySQL и ClickHouse. База выбирается полем `engine`
  (`postgresql` — понимает также `postgres`, `pg`, `постгрес`; `mysql`; `clickhouse`). `overview` — кластеры
  (без `engine` — сразу все три базы); `card` — карточка: состояние, ресурсы, хосты и **готовая строка
  подключения**; `hosts` — хосты (зоны, роли MASTER/REPLICA, здоровье, диск); `databases` — базы;
  `users` — пользователи и их доступ; `logs` — записи за `minutes` минут (`serviceType`: PostgreSQL —
  POSTGRESQL/POOLER/REPACK, MySQL — MYSQL/POOLER, ClickHouse — CLICKHOUSE/KEEPER); `operations` — история
  операций; `presets` — классы хостов (ядра, память, зоны — список отдаёт само облако); `start` / `stop` —
  питание; `create` — создать кластер; `delete` — удалить.
  **Что знать до первого вызова:** (1) адрес подключения — это ИМЯ ХОСТА (`c-…rw.mdb.yandexcloud.net`), а не
  кластера: точки входа у кластера нет, поэтому строку собирает `card` по хосту-мастеру; порт PostgreSQL — 6432
  (пулер), MySQL — 3306, ClickHouse — 9440; (2) **ПАРОЛЬ пользователя облако отдаёт РОВНО ОДИН раз** — в ответе
  на `create`, дальше его не покажет ни список, ни консоль, поэтому сразу убирай его в хранилище секретов
  (`ycSecret`), а не в переписку; (3) **создание ПЛАТНОЕ**: класс тарифицируется почасово и круглосуточно, поэтому
  назови пользователю ориентир цены (`ycBilling { action: "price", query: "PostgreSQL" }`) и только потом вызывай
  с `confirm: true`; обязательные поля: `name`, `version` (PostgreSQL — 11…18, MySQL — 5.7/8.0/8.4, ClickHouse —
  например 24.8), `preset` (id из `presets`) и `subnet` (сеть определится по ней, `ycVpc { action: "subnets" }`);
  (4) `stop` экономит деньги за вычисления, но диск и **резервные копии** тарифицируются и у остановленного
  кластера; (5) **удаление необратимо** и забирает резервные копии вместе с кластером — только с `confirm: true`
  после согласия; при включённой защите от удаления (`deletionProtection`) облако откажет, и сначала её надо снять
  в консоли. Разрешения: `create` — «создавать ресурсы», `start`/`stop` — «менять контейнеры и правила сети»,
  `delete` — «удалять ресурсы». Это НЕ YDB-база из `ycDb`: там Document API, здесь обычные SQL-кластеры.
- `ycIg { action, group, name, subnet, size, cores, memoryGb, coreFraction, diskSizeGb, diskType, imageFamily, imageId, zone, platformId, publicIp, preemptible, securityGroups, serviceAccountId, sshPublicKey, sshUser, confirm }` —
  ГРУППЫ ОДИНАКОВЫХ МАШИН (Instance Groups). `list` — группы каталога; `card` — карточка:
  шаблон, машины, операции; `instances` — машины группы; `operations` — история операций;
  `create` — создать группу; `start` / `stop` — питание; `delete` — удалить группу.
  **Главное отличие от `ycCompute`:** группа это не «несколько машин», а другой ресурс — она
  САМА создаёт машины по шаблону (`instanceTemplate`), держит их число (`scalePolicy`) и
  ПЕРЕСОЗДАЁТ удалённые руками. Значит: число машин меняют размером группы, а не удалением
  машин по одной, и «удалить машину» тут бессмысленно — она вернётся.
  **Что знать до первого вызова:** (1) платят МАШИНЫ группы — как обычные машины Compute
  Cloud, за каждый час работы, поэтому ориентир цены называй ДО создания (`ycCosts { service:
  "compute" }`, точная цена за час — `ycBilling { action: "price", query: "Compute" }`) и вызывай
  `create` только с `confirm: true` после согласия; (2) группа стоит в ОДНОЙ зоне — зоне
  подсети, поэтому `subnet` обязателен (`ycVpc { action: "subnets" }`), а зона берётся от неё;
  (3) без `publicIp: true` внешнего адреса у машин нет, а без `securityGroups` останется группа
  по умолчанию сети — она закрывает SSH снаружи, поэтому для доступа нужны своя группа и
  правило на 22 порт ТОЛЬКО с адреса пользователя (`/32`); (4) **удаление необратимо**: `delete`
  забирает ВМЕСТЕ с группой все её машины и их диски — снимки делай заранее, и только с
  `confirm: true` после согласия; при `deletionProtection` облако откажет, и защиту надо снять
  в консоли. Разрешения: `create` — «создавать ресурсы», `start`/`stop` — «менять контейнеры и
  правила сети», `delete` — «удалять ресурсы». Это НЕ `ycCompute`: там одна машина, здесь парк
  одинаковых машин под одним шаблоном.
- `ycAlb { action, lb, group, router, name, kind, ips, subnet, listener, port, certificate, targetGroup, backendGroup, healthPath, host, pathPrefix, pathExact, address, securityGroups, confirm }` —
  ВХОД В ПРИЛОЖЕНИЕ С УЛИЦЫ (Application Load Balancer). Это ЧЕТЫРЕ разных ресурса одной семьи, и путать их нельзя:
  **группа целей** (`targets`, `targetnew`, `targetadd`, `targetremove`, `targetdel`) — список АДРЕСОВ машин,
  знает только адрес и подсеть; **HTTP-роутер** (`routers`, `routernew`, `routerdel`) — правила «домен и путь →
  группа бэкендов»; **балансировщик** (`list`, `card`, `lbnew`, `lbstart`, `lbstop`, `lbdel`) — адреса, зоны и
  СЛУШАТЕЛИ; **группа бэкендов** (`backends`, `backnew`, `backdel`) — куда ведут маршруты: здесь живут ПОРТ целей
  и проверки здоровья.
  **Порядок такой:** `targetnew` (адреса машин) → `backnew` (группа бэкендов: `kind` — http/grpc/stream,
  `port` — порт, который слушают ЦЕЛИ, `healthPath` — проверка здоровья; у потока порт обязателен) → `routernew` (нужна СУЩЕСТВУЮЩАЯ группа бэкендов — список в
  `backends`; пустой список значит «роутер создавать некуда», и это надо сказать человеку, а не выдумывать id) →
  `lbnew` (слушатель: `http` — через роутер, `https` — роутер и сертификат Certificate Manager со статусом
  `Issued`, `stream` — поток TCP на группу бэкендов). Смешивать HTTP и TCP в одном TLS-слушателе нельзя.
  **Деньги:** платит БАЛАНСИРОВЩИК — ресурсные единицы и сам ресурс за час, даже когда трафика нет, поэтому
  `lbnew` только с `confirm: true` после согласия, а ориентир даёт `ycBilling { action: "price", query: "Application
  Load Balancer" }`. Группа целей и роутер бесплатны. `lbdel` уносит слушатели и адреса — домен перестанет
  открываться; `routerdel` оставляет слушатель без ответа; `targetdel` теряет список целей — всё с `confirm: true`.
  **Адрес балансировщика — это адреса его СЛУШАТЕЛЕЙ:** пока слушатель не создан, адреса нет, и DNS-запись
  (`ycDns`) вешают только после создания, иначе домен будет смотреть в никуда. Подсеть задаёт зону узла (как у
  `ycIg`), а для отказоустойчивости узлы ставят в двух зонах — это отдельная правка, а не второй балансировщик.
  **Здоровье целей** (здорова/не отвечает) показывает `health`: он спрашивает пару «группа бэкендов + группа
  целей» у балансировщика (`health { lb, targetGroup, backendGroup }`) и отвечает ПО ЗОНАМ; без проверок
  здоровья в группе бэкендов облако считает здоровой каждую цель. `backdel` удаляет группу бэкендов только
  когда на неё никто не смотрит: роутер или слушатель-поток держат её, и их надо назвать словами, а не
  пересказывать отказ облака.
- `ycVpc { action, name, network, zone, cidr, group, direction, protocol, port, sourceGroup, address }` — СЕТЬ VPC:
  подсети, группы безопасности и статические адреса. `list` — общая картина (сети, подсети, группы, адреса) и
  предупреждение о простаивающих адресах; `subnets` — подсети (зона, диапазон, сеть); `addsubnet` — создать
  подсеть (`name`, `network`, `zone` — `ru-central1-a`, `cidr` — `10.10.0.0/24`; без `cidr` подберу свободный
  диапазон и скажу, какой выбрал); `delsubnet` — удалить подсеть; `groups` — группы безопасности с их правилами;
  `addgroup` — создать группу; `delgroup` — удалить группу; `addrule` / `delrule` — добавить и убрать правило
  (`group`, `direction` — `ingress` вход или `egress` выход, `protocol` — tcp/udp/icmp/any, `port` — `22` или
  `"8000-8010"`, `cidr` — `203.0.113.10/32`, либо `sourceGroup`); `addresses` — статические адреса (привязан или
  ПРОСТАИВАЕТ); `reserve` — закрепить адрес (`name`, `zone`); `release` — освободить адрес.
  **Что нужно виртуальной машине:** подсеть + группа безопасности + правило на порт 22 ТОЛЬКО с адреса
  пользователя (`/32`). Правило `cidr: "0.0.0.0/0"` пускает к машине кого угодно — так делать нельзя, и скажи
  об этом пользователю прямо. Группа без правил не пускает и не выпускает НИЧЕГО: создал группу — добавь правило.
  `addsubnet`, `addgroup`, `reserve` требуют «создавать ресурсы», `addrule` / `delrule` — «менять контейнеры и
  правила сети», `delsubnet`, `delgroup`, `release` — «удалять ресурсы». Простаивающий статический адрес
  тарифицируется так же, как привязанный, а освобождённый IP вернуть нельзя — не закрепляй адрес «про запас».
- `ycCompute { action, instance, name, preset, subnet, cores, memoryGb, coreFraction, diskSizeGb, diskType, publicIp,
  staticAddress, sshPublicKey, sshUser, preemptible, dataDiskSizeGb, disk, snapshot, keep, olderThanDays, dryRun,
  minutes, lines, deleteDisks, releaseAddress, confirm }` — МАШИНЫ (Compute Cloud):
  `list` — машины каталога, остановленные отдельно и ПЛАТНЫЕ ХВОСТЫ (диски без машины, снимки удалённых
  дисков, простаивающие адреса); `card` — одна машина: где живёт, какие диски и адреса, сколько стоит и что с
  ней можно сделать; `presets` — готовые конфигурации с ценой (`micro`, `small`, `medium`, `full`); `create` —
  создать машину (`name`, `preset` или `cores` + `memoryGb`, `subnet` — ОБЯЗАТЕЛЬНА, `diskSizeGb`, `diskType`,
  `publicIp`, `staticAddress` — привязать закреплённый адрес, `sshPublicKey` — без ключа войти будет НЕЛЬЗЯ:
  у машины нет ни пароля, ни экрана); `start` / `stop` / `restart` — питание (`stop` реально экономит: за
  выключенное время не платят); `delete` — удалить машину (`deleteDisks` — вместе с дисками, по умолчанию диски
  остаются и ПРОДОЛЖАЮТ тарифицироваться; `releaseAddress` — освободить статический адрес: вернуть именно его
  уже нельзя); `disks` — диски каталога с ценой и пометкой «ни к чему не привязан»; `snapshot` — снимок диска
  или машины (`disk` или `instance`); `delsnapshot` — удалить снимок; `cleansnapshots` — чистка старых снимков
  (`keep` — сколько последних на каждый диск оставить, `olderThanDays`; по умолчанию `dryRun` — только показать,
  что удалит); `restoredisk` — восстановить диск из снимка (`snapshot`, `zone`, `diskName`): это НОВЫЙ диск, и
  машины у него нет; `serial` — serial-консоль, то есть «экран» машины: видно, поднялась ли служба и что мешает
  запуску (`lines` — сколько последних строк); `metrics` — нагрузка из Monitoring (`minutes`): работает машина
  или простаивает; `leftovers` — только платные хвосты.
  **Порядок работы:** `ycVpc` (подсеть + группа безопасности + правило на 22 порт ТОЛЬКО с адреса пользователя)
  → `presets` → `create` с `confirm: true` после согласия с ценой → `serial` / `metrics`, чтобы убедиться, что
  машина правда жива. Машина платит за КАЖДЫЙ час работы, а её диски — всегда: и когда она остановлена, и после
  её удаления. Поэтому перед удалением предложи `snapshot`, а хвосты ищи через `leftovers`. Зона машины, зоны
  подсети и статического адреса обязаны совпадать — подсеть в другой зоне облако отбивает ошибкой. `create`,
  `snapshot` и `restoredisk` требуют «создавать ресурсы», `start` / `stop` / `restart` — «менять контейнеры и
  правила сети», `delete`, `delsnapshot` и `cleansnapshots` с `dryRun: false` — «удалять ресурсы». Приватный ключ
  SSH делает ЧЕЛОВЕК в панели: агент принимает только готовую публичную строку при создании машины.
- `ycIam { action, account, role, task, kind, keyId, filter }` — IAM: сервисные аккаунты («роботы»), их роли и
  ключи. Всё, что работает САМО (выкатка, бэкап, скрипт, машина, выгрузка из базы), обязано иметь свой аккаунт с
  УЗКОЙ ролью: тогда чужие права и утечка одного ключа не касаются остальных. `list` — аккаунты с ролями,
  ключами и предупреждениями («без ролей», «ключей нет», «ключ не использовался»); `card` — карточка одного
  (`account` — имя или id): чем занят, что может, чем входит и что сломается при удалении; `keys` — ключи
  аккаунта; `rolemap` — роли человеческими словами и чем они опасны (это знание приложения: работает даже без
  подключённого облака); `suggest { task }` — каких ролей ХВАТАЕТ для задачи (`site`, `vm`, `containers`,
  `secrets`, `db`, `logs`, `readonly`); `roles { filter }` — живой список ролей облака. Изменения:
  `create { name, description }`, `update { account, newName, description }`, `delete { account }`,
  `grant` / `revoke { account, role }`, `newkey { account, kind }`, `delkey { kind, keyId }`.
  **Ключи бывают трёх видов:** `kind: "access"` — S3-совместимый (Object Storage, скрипты, бэкапы);
  `"api"` — вызов API сервисов (API Gateway, функции); `"authorized"` — пара для SSH к машине (публичная часть
  уходит в метаданные). **Секрет облако отдаёт РОВНО ОДИН раз** — в ответе на создание; ни в списке, ни в
  карточке его нет и не будет (там только маска вида `****Ab12cd`). Поэтому `newkey` требует `confirm: true`, а
  секрет сразу уходит в хранилище (`ycSecret`), а не в переписку и не в файлы проекта. Ключ работает ровно с
  ролями аккаунта: без роли он бесполезен, а с `editor` открывает почти всё.
  **Роли:** примитивные (`viewer`, `editor`, `admin`, `auditor`) действуют на ВЕСЬ каталог — предлагай их
  последними, а сначала узкие (`storage.editor`, `compute.editor`, `serverless.containers.editor` +
  `container-registry.images.puller`, `lockbox.payloadViewer`, `ydb.editor`, `logging.viewer`). Привязки
  меняются ДЕЛЬТАМИ (ADD/REMOVE): снятие одной роли не задевает остальные, но результат всё равно проверяется
  перечитыванием — если роль не появилась в списке, значит, прав на выдачу не хватило. `create` и `newkey`
  требуют «создавать ресурсы», `update`, `grant` и `revoke` — «менять контейнеры и правила сети», `delete` и
  `delkey` — «удалять ресурсы». Удаление аккаунта забирает его ключи и роли: сначала назови пользователю, что
  именно перестанет работать. **IAM бесплатен** — платят за ресурсы, к которым роли дают доступ, так что
  «выдать editor» дешевле не станет, а опаснее станет.
- `ycFunctions { action, function, runtime, entrypoint, zipFile, memoryMb, timeoutSec, tag, payload }` —
  CLOUD FUNCTIONS: функции, их версии, теги и вызов (раньше их не было видно вовсе). Главное правило сервиса:
  **у функции нет кода — код живёт в ВЕРСИИ**, и вызов всегда попадает в какую-то версию. `list` — что есть в
  каталоге и что с этим не так; `card` — одна функция словами (что отвечает, чем её звать, что будет при
  удалении); `versions` — версии (id, язык, память, статус, теги, переменные); `runtimes` — доступные языки
  выполнения; `create` — создать функцию; `update` — имя, описание, метки; `deploy` — создать ВЕРСИЮ (только так
  меняется код); `invoke` — вызвать и увидеть ответ её кода; `tag` / `untag` — поставить и снять тег версии;
  `delversion` — удалить версию; `delete` — удалить функцию ВМЕСТЕ со всеми версиями (`confirm: true`);
  `public` / `private` — открыть функцию всему интернету и закрыть; `access` — кому разрешено вызывать.
  **Боевая версия.** По умолчанию отвечает САМАЯ НОВАЯ созданная версия — это и значит виртуальный тег
  `$latest`; назначить его руками нельзя. Поэтому адрес без тега меняет поведение от каждой выкатки, а
  постоянный тег (`v1`, `prod`) даёт стабильную ссылку `?tag=v1`, которая не поедет. Если человеку важна
  неизменность — сначала выкати, потом поставь тег и отдай ему адрес с тегом.
  **Код версии** приходит из `zipFile` (путь к ZIP-архиву), `sourceVersionId` (копия прежней версии — меняются
  только переменные и память) или `package { bucketName, objectName }` (архив уже в бакете; больше 8 МБ — только
  так). Обязательны `runtime` (номер языка входит в идентификатор: `nodejs22`, не `node22`) и `entrypoint`
  (`index.handler`). Память — в мегабайтах, округляется ВВЕРХ кратно 128 МБ (128…8192); `timeoutSec` — до 600 с,
  дольше функция работать не может в принципе. Переменные — `environment`, секреты Lockbox — `secrets`, доступ к
  сети — `networkId`.
  **Вызов** идёт на публичный адрес `functions.yandexcloud.net`, а не в API сервиса. Закрытую функцию может
  позвать только тот, у кого есть роль `serverless.functions.invoker` (иначе 403 — это объясняется словами), а
  `public` выдаёт эту роль `allUsers`, то есть ОТКРЫВАЕТ функцию кому угодно из интернета: зови его только по
  явной просьбе и предупреди, что за чужие вызовы платить будет владелец.
  **Цена.** Функция и её версии бесплатны: платят за вызовы и время выполнения, первые 1 000 000 вызовов и
  10 ГБ×час в месяц не тарифицируются. Для «редко зовут» и «по расписанию» это ДЕШЕВЛЕ машины, и об этом стоит
  сказать, когда человек собирается держать ВМ ради одной задачи. Оценка — через `ycCosts { service:
  "cloudFunctions" }`. Логи функции: `ycLogs { service: "cloudFunctions", id: "<id функции>" }` (тип ресурса
  `serverless.function`).
  **Права:** `create` и `deploy` — «создавать ресурсы», `update`, `tag`, `public` — «менять контейнеры и правила
  сети», `delete` и `delversion` — «удалять ресурсы». Удаление функции забирает все версии и теги, поэтому
  требует `confirm: true` и предупреждения о том, что перестанет отвечать.
- `ycBilling { action, account, query, serviceId, currency }` — ДЕНЬГИ В ОБЛАКЕ: что уходит и на что.
  `overview` — сводка одним ответом (аккаунт, баланс, пороги, хвосты); `accounts` — платёжные аккаунты и баланс;
  `account` — один аккаунт словами; `budgets` — пороги-бюджеты; `price` — НАСТОЯЩАЯ цена из каталога облака по
  словам (`query: "быстрый диск"`, `"ядро"`, `"память"`, `"функция"`, `"запрос"`); `services` — что вообще
  тарифицируется; `leaks` — «платные хвосты» в рублях за месяц.
  **Расход облако по API не отдаёт** — ни суммы счёта, ни детализации: в Billing API есть только платёжные
  аккаунты, бюджеты, каталог услуг и каталог цен (SKU). Точные цифры живут в консоли (Биллинг → Расходы) и в
  выгрузке детализации в бакет. Поэтому на «сколько я потратил» честный ответ такой: точной суммы тут нет, но
  вот баланс, пороги и то, за что платят по факту. Не выдумывай цифру расхода.
  **Биллинг — не каталог.** Он привязан к ПЛАТЁЖНОМУ аккаунту и требует роли `billing.viewer`; без неё приходит
  403, и это надо объяснить человеку словами. `folderId` для баланса и порогов не нужен — каталог нужен только
  хвостам (`overview`, `leaks`).
  **Баланс — это не расход:** отрицательный баланс означает, что облако скоро остановит ресурсы, поэтому о нём
  говорят сразу. **Порог-бюджет** — предупреждение, а не счёт: он не показывает потраченное, он заранее пишет на
  почту. Создать бюджет по API нельзя без id пользователя для уведомлений — отправляй человека в консоль
  (Биллинг → Бюджеты).
  **Хвосты** (`leaks`) считаются в деньгах: диск без машины, снимок удалённого диска, простаивающий статический
  адрес, снимки старше 90 дней и остановленные машины (их диски платят всегда). Перед удалением предложи
  пользователю снимок и получи его согласие — удаление необратимо. Образы реестра и версии объектов в бакете
  считай их инструментами (`ycRegistry { action: "images" }`, `ycStorage { action: "list" }`).
  **Цены.** `price` показывает то, что облако говорит СЕЙЧАС, а наши ориентиры (`ycCosts`) посчитаны по
  документации и помечены датой: если числа разошлись — верь облаку и скажи пользователю, что ориентир устарел.
  Инструмент ТОЛЬКО читает: разрешений не требует и ничего не меняет.
- `ycCdn { action, certificate, domains, cname, bucket, resource, paths, group, origins, confirm }` — HTTPS-САЙТ
  НА СВОЁМ ДОМЕНЕ: сертификат Certificate Manager (бесплатный, Let's Encrypt) и ресурс Cloud CDN, который его
  носит и раздаёт файлы из бакета. Действия: `overview` (сертификаты и ресурсы разом), `certs` / `cert`
  (список / карточка: для каких доменов, чем подтверждается, когда истекает, что не так), `certnew` (выпустить),
  `certimport` (загрузить свой сертификат с ключом), `certupdate` / `certdel`, `cdn` / `cdninfo`,
  `cdncreate` / `cdnupdate` / `cdnpurge` / `cdndel`, `origins` / `origincreate` / `originupdate` / `origindel`.
  **Цена:** сертификаты бесплатны (Certificate Manager не тарифицируется), платит CDN-ресурс — 150 ₽ в месяц за
  КАЖДЫЙ ресурс пакетом (в пакет входят 150 ГБ исходящего трафика и 100 млн запросов), сверх пакета 1,054 ₽ за ГБ
  и 1 ₽ за 100 тыс. запросов. Деньги уходят даже при нулевом трафике, поэтому `cdncreate` требует `confirm: true`
  после согласия пользователя, а `ycCosts { service: "cdn" }` даёт ориентир ДО создания.
  **Права:** `certnew`, `certimport`, `cdncreate`, `origincreate` — «создавать ресурсы»; `certupdate`,
  `cdnupdate`, `cdnpurge`, `originupdate` — «менять контейнеры и правила сети»; `certdel`, `cdndel`, `origindel` —
  «удалять ресурсы» (+ `confirm: true` и предупреждение о том, что перестанет работать).
  Подробный порядок работы и все грабли — в разделе «HTTPS-сайт из бакета» ниже.
- `ycAi { action, text, texts, target, targets, source, file, files, langs, model, voice, voices, lang, format, speed, emotion, out, topic, sampleRateHertz, prompt, system, temperature, maxTokens }` —
  ЯНДЕКС AI: перевод, текст с картинки, речь и модели AI Studio. Авторизация та же, что у всего облака (OAuth → IAM),
  отдельного ключа API заводить НЕ нужно. Действия: `translate` (перевести), `languages` (языки перевода из
  облака), `ocr` (текст с картинки или PDF), `voices` (голоса SpeechKit), `speak` (текст в звук), `listen`
  (звук в текст), `models` (модели AI Studio каталога), `tokens` (посчитать токены текста — бесплатно),
  `complete` (ответ модели), `embed` (вектор текста).
  **Списки приветствуются:** `targets: ["en", "de"]` — перевести сразу на несколько языков, `texts: ["…", "…"]` —
  сразу несколько строк, `files: ["a.png", "b.jpg"]` — распознать пачку снимков, `voices: ["alena", "filipp"]` —
  озвучить одним и тем же голосами на выбор и сравнить. Каждый целевой язык — ОТДЕЛЬНЫЙ запрос.
  **AI Studio (модели каталога, ответ модели, токены и векторы):** порядок такой — сначала `models` (список
  моделей каталога, бесплатно), потом `tokens` (сколько токенов в тексте — БЕСПЛАТНО и до платного запроса:
  у каждой модели свой токенизатор), потом `complete`. У `complete`: `prompt` — запрос, `system` — роль модели,
  `temperature` 0…1 (по умолчанию 0.3), `maxTokens` — длина ОТВЕТА (1…32000, по умолчанию 2000; вход считается
  отдельно). Модели: `yandexgpt-5-lite` (дешёвая), `yandexgpt-5.1`, `yandexgpt-5-pro`, `aliceai-llm` (контекст
  128k); `model` принимает и полный адрес `gpt://<каталог>/<модель>`. `embed` — вектор для поиска по смыслу:
  документы и запросы векторизуют РАЗНЫМИ моделями (`text-search-doc` и `text-search-query`), их пространства
  несовместимы. **Деньги AI Studio:** `models` и `tokens` бесплатны, `complete` и `embed` платные по токенам —
  ответ называет тариф до и после запроса (Lite 0.2 ₽, Pro 5.1 0.8 ₽, Pro 5 1.2 ₽ за 1000 токенов; Alice —
  0.5 ₽ вход и 1.2 ₽ выход; векторы 0.0101 ₽ за 1000 токенов).
  **Когда что брать:** скриншот с текстом или скан документа → `ocr` (модели: `page` — обычный, `handwritten` —
  рукописный, `table` — таблицы, `markdown`, `mathmarkdown`; языки `langs: ["ru", "en"]`); перевод письма,
  чужой документации, подписи на картинке → `translate` (если язык источника неизвестен, оставь `source` пустым —
  облако определит само и скажет, с какого перевело); «озвучь ответ» → `speak` (файлы ложатся в рабочую папку
  агента, открыть — `openPath`); «расшифруй голосовое» → `listen` (ogg/opus, mp3, lpcm).
  **Пределы, чтобы не удивляться:** картинка — до 10 МБ, звук для `listen` — до 1 МБ (примерно минута сжатой
  речи; дольше — резать на части); `lpcm` требует `sampleRateHertz`; эмоции (`good` / `evil`) понимают только
  русские голоса. **Деньги:** все сервисы тарифицируются по запросу (перевод и OCR — по символам, SpeechKit —
  по длине звука, AI Studio — по токенам; `models` и `tokens` бесплатны), а `translate` с пятью языками —
  это пять запросов: не гоняй по одному языку за раз.
  **Разрешений не требует** (это не ресурсы каталога, а запросы), но `speak` пишет файл в рабочую папку агента.
- `ycMonitor { action, metric, query, service, resource, minutes, aggregation, maxPoints, gapFilling, limit }` —
  МЕТРИКИ каталога (Yandex Monitoring). Действия: `overview` (метаданные: какие метрики вообще есть, их типы и
  метки), `names` (метрики одного ресурса по метке `service` + `resource_id`), `metrics` (данные за период).
  **Сначала `overview` / `names`, а не метрика по памяти:** имена метрик и наборы меток меняются от сервиса к
  сервису — у машины это `cpu_usage` в миллисекундах времени CPU, у другого сервиса метрика называется иначе.
  **Метки у метрик облака одинаковые:** `service` (сервис) и `resource_id` (ресурс). Инструмент собирает из них
  запрос сам: `metric: "cpu_usage", service: "compute", resource: "<id>"` → `cpu_usage{service="compute",
  resource_id="<id>"}`; вместо сборки можно отдать готовый `query` целиком. **Прореживание обязательно:** за
  сутки сырых точек десятки тысяч, поэтому у запроса есть `maxPoints` (сколько точек оставить, по умолчанию 30;
  облако требует больше 10), `aggregation` (чем сводить: AVG/MAX/MIN/SUM/LAST/COUNT, по умолчанию AVG) и
  `gapFilling` (что с пропусками: NULL/NONE/PREVIOUS). **Ответ — сводка по ряду** (среднее, максимум, последнее,
  число точек), а не таблица: если нужно «работает или простаивает», этого достаточно, а грузить точки в ответ
  не нужно. Пустой ряд — не ошибка сервиса, а либо неверное имя метрики, либо `resource_id` не тот: проверь
  `names` по этому ресурсу. **Порог с уведомлением (алерт) этим инструментом поставить НЕЛЬЗЯ** — публичный
  справочник API у Monitoring знает только данные метрик (MetricsData) и их метаданные (MetricsMeta), отдельного
  REST для алертов у облака нет: они настраиваются в консоли Monitoring. Не выдумывай действие «создать алерт»
  и не обещай пользователю слежение за порогом — предложи посмотреть метрики (частая причина вопросов —
  «почему машина тормозит» и «не простаивает ли она зря»). Инструмент только читает: разрешений не требует.
- `ycLogs { id, service, sinceHours, limit }` — логи ресурса за последние 3 часа (окно и лимит настраиваются).
  Читаются ВНУТРЕННИМ API приложения (Cloud Logging: лог-группы по REST, записи по gRPC с хоста `log-reading`) —
  внешний `yc` CLI для логов НЕ нужен, `ycInstall` не требуется.
- `ycInstall { force }` — официальный `yc` CLI внутрь папки приложения (`userData/bin`, системных прав не требует)
  и в PATH всех команд агента. Нужен, только если в песочнице требуется сама команда `yc`.
  Если `yc` ответит «The token is invalid» — повтори вызов через минуту: приложение продлевает IAM само.

## HTTPS-сайт из бакета: `ycCdn`

Задача звучит как «сделай мой сайт доступным по https://мой-домен», а состоит из двух сервисов: **Certificate
Manager** выпускает сертификат, **Cloud CDN** его носит и раздаёт файлы из бакета. Порядок шагов важен, потому
что каждый следующий зависит от предыдущего:

1. **Бакет с сайтом.** Файлы (`index.html` и остальное) лежат в бакете, у бакета включён публичный доступ на
   чтение (`ycStorage { action: "public", bucket: "имя" }`) и хостинг статики с главной страницей. Без главной
   страницы по адресу «/» будет список файлов или 404.
2. **Сертификат** — `ycCdn { action: "certnew", name: "site-cert", domains: ["cdn.example.com"] }`. Бесплатно.
   Из ответа берётся **запись подтверждения** (её печатает и `cert`, и `certnew`).
3. **Подтверждение домена.** Запись добавляется в DNS-зону домена: `_acme-challenge.<домен>` CNAME
   (`<id сертификата>.cm.yandexcloud.net.`) — или TXT, но CNAME лучше. Если домен ведёт Cloud DNS — это
   `ycDns { action: "add", ... }`; если домен у другого регистратора — запись добавляет человек, и об этом надо
   попросить прямо. Потом ждём: статус сертификата меняется на `Issued` сам (от часа до суток), жать нечего.
4. **CDN-ресурс** — `ycCdn { action: "cdncreate", cname: "cdn.example.com", bucket: "имя-бакета",
   certificate: "site-cert", confirm: true }`. Платно (150 ₽/мес за ресурс), только после согласия.
5. **CNAME домена на адрес провайдера:** `<домен> CNAME <providerCname>` — адрес показывает `cdninfo`, и без
   этой записи домен не ведёт на CDN вообще.
6. **Проверка:** `ycCdn { action: "cdninfo", resource: "cdn.example.com" }` — https, источник, что в DNS и что
   не так. Изменения в CDN применяются до 15 минут, поэтому «сразу не открылось» — это нормально, а не повод
   создавать второй ресурс.

**Грабли, на которых теряют время чаще всего:**

- **Домены сертификата изменить нельзя.** Никакого «допишу домен потом»: другой набор доменов — только новый
  сертификат (`certnew`), и старый можно удалить.
- **Пока домен не подтверждён — HTTPS не работает.** Сертификат в статусе `Validating` не привязать к живому
  сайту: сначала запись, потом выпуск. Если за неделю не подтвердить, сертификат станет `Invalid` — лечится
  только НОВЫМ запросом.
- **Запись подтверждения ровно одна.** CNAME **или** TXT; обе сразу ломают проверку у кеширующих серверов. На
  имени `_acme-challenge.<домен>` не должно быть других записей. CNAME подтверждается один раз и продления
  проходят сами, TXT пришлось бы обновлять каждые 60 дней.
- **Маску (`*.example.com`) файлом на сайте подтвердить нельзя** — только DNS-записью. Модуль отбивает такой
  запрос до обращения в облако.
- **Сертификат и CDN-ресурс — в одном каталоге.** Иначе облако отказывает невнятно.
- **У бакета-источника нужен свой заголовок Host** (`<бакет>.website.yandexcloud.net`) — иначе бакет отвечает
  CDN-серверам «404», и выглядит это как «CDN настроен, а сайта нет». Когда ресурс создаётся с `bucket`, модуль
  ставит заголовок сам.
- **Основной домен ресурса задаётся один раз**: поля `cname` в API обновления нет вовсе. Нужен другой адрес —
  новый ресурс и перевод DNS.
- **Сначала выпущенный сертификат, потом ресурс:** привязка невыпущенного сертификата оставит сайт по http.
- **Загруженный (imported) сертификат не продлевается сам.** Видеть дату и напоминать — обязательно, иначе
  сайт умрёт в день окончания. Для этого и существует бесплатный сертификат от облака.
- **Обновил файлы — почисти кэш:** `ycCdn { action: "cdnpurge", resource: "домен", paths: ["/index.html", "/img/*"] }`
  (или `all: true`). Звёздочка работает только в КОНЦЕ пути, путей за раз не больше 10, запросов — один в
  минуту, а сама очистка идёт до 15 минут.
- **Удаление необратимо.** Удаление сертификата забирает его у сайта (браузер покажет «сертификат
  недействителен»), удаление ресурса оставляет DNS-записи в никуда, а предоплаченный пакет трафика сгорает и не
  переносится. Поэтому сначала `confirm`-ответ с перечислением последствий, и только потом удаление по согласию.

## Контейнеры вглубь: `ycContainer`

Консоль YC показывает контейнер вкладками, и `ycContainer` повторяет их один в один.
Чтение доступно всегда; `deploy` / `rollback` / `update` требуют чекбокса
«Разрешить агенту менять контейнеры и правила сети» (по умолчанию выключен).

```
ycContainer { action: "overview",  container: "<имя или id>" }
ycContainer { action: "revisions", container: "…", limit: 15, filter: "status=\"OBSOLETE\"" }
ycContainer { action: "revision",  container: "…", revisionId: "bba5…" }
ycContainer { action: "deploy",    container: "…", image: "cr.yandex/<registry-id>/<image>:tag", env: { "NODE_ENV": "production" } }
ycContainer { action: "rollback",  container: "…", revisionId: "bba5…" }
ycContainer { action: "update",    container: "…", name: "api", description: "Прод API", labels: { env: "prod" } }
```

- **overview** — статус, дата создания, URL, число ревизий и ПОЛНЫЕ настройки активной ревизии.
- **revisions** — список (id, статус, дата, образ, ресурсы). `★ активна` — та, что принимает трафик.
  `filter` принимает только поля `Revision.status` и `Revision.runtime`: `status="ACTIVE"`, `runtime="http"`.
- **revision** — детали одной ревизии.
- **deploy** — создать ревизию. Настройки берутся из активной ревизии, а всё переданное их переопределяет:
  `env` ДОБАВЛЯЕТСЯ к прежним переменным (`envReplace: true` — заменить набор целиком), `command`/`args`
  переопределяют ENTRYPOINT/CMD образа, `memoryMb` (кратно 128), `cores`, `timeoutSec`, `concurrency`,
  `serviceAccountId`, `networkId`, `minInstances`, `secrets` (Lockbox), `runtime: "task"`.
  **Образ, переменные и ресурсы меняются только новой ревизией** — «отредактировать работающий контейнер»
  в YC нельзя, редактор всегда заканчивается кнопкой «Создать ревизию».
- **rollback** — вернуть контейнер на старую ревизию (в консоли это «сделать активной»).
  Удалить ревизию нельзя: такого метода в API нет, есть только откат.
- **update** — имя, описание и метки самого контейнера (на запущенный код не влияет).

## Публичный вызов и логи

- Публичный вызов идёт по `URL` контейнера (виден в `overview`), но только если у сервисного аккаунта
  есть роль `serverless.containers.invoker` на каталог — это настраивает `ycDeploy { public: true }`.
- Логи ревизии: `ycLogs { service: "serverlessContainers", id: "<id контейнера>" }` (не ревизии).

## Токен и каталог

Подставляются автоматически: `YC_IAM_TOKEN` (свежий IAM-токен), `YC_CLOUD_ID`, `YC_FOLDER_ID`.
`yc init` не нужен.

## Ключи сервисов для ycList / ycCreate

`apiGateway`, `certificateManager`, `cdn`, `dns`, `logging`, `postbox`, `containerRegistry`, `iam`,
`lockbox`, `ydb`, `storage`, `serverlessContainers`, `vpc`.
