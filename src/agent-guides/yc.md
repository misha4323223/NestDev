# Yandex Cloud (yc-инструменты)

Справочник агента. Читается вручную: `agentGuide { name: "yc" }` (или `readFile { path: "agent-guide:yc" }`).
Подключается автоматически, когда в задаче появляется облако (группа `cloud`).

## Порядок работы

1. `ycStatus` — ВСЕГДА начинай отсюда: авторизован ли пользователь (Настройки → «☁️ Yandex Cloud»),
   какой каталог выбран, какие разрешения выданы агенту, счётчики ресурсов по всем сервисам.
2. `ycList` — список ресурсов. `service` — ключ сервиса; без `service` — сводка по всем.
   Возвращает имена и `id`. Результат любой операции проверяй `ycList`, а не по памяти.
3. Создание/удаление/деплой — только по ЯВНОЙ просьбе пользователя и при включённых чекбоксах
   разрешений: ресурсы платные, удаление необратимо.

## Инструменты

- `ycCreate { service, name }` — создание ресурса в выбранном каталоге. `name` — латиница, цифры, дефис.
  Создание доступно для: `ydb`, `lockbox`, `containerRegistry`, `storage`, `dns`, `serverlessContainers`, `vpc`.
- `ycDelete { service, id }` — удаление по `id` (виден в `ycList`). Необратимо и может удалить данные.
- `ycDeploy { directory, name, public }` — деплой папки проекта в Serverless Containers: собирает Docker-образ
  (или генерирует Dockerfile по типу проекта), загружает в Container Registry, создаёт/обновляет
  Serverless Container, при `public: true` настраивает публичный доступ → возвращает URL.
  Требует Docker на ПК и разрешение на создание ресурсов. Деплой платный.
- `ycSecret { action, secret, entries }` — секреты Lockbox. `list` — секреты каталога; `versions` — версии секрета
  (id, дата и ИМЕНА ключей: значения API не отдаёт никогда); `putversion` — новая версия со значениями
  (`entries: { "API_KEY": "…" }`, можно списком `[{ key, value }]`). `putversion` — это создание: нужно разрешение
  «Разрешить агенту создавать ресурсы» и явная просьба пользователя. **Секрет без версии бесполезен**: ревизия
  ссылается на ключ, которого нет. Порядок: `ycCreate { service: "lockbox", name: "app-env" }` → `ycSecret { action: "putversion" }`
  → `ycContainer { action: "deploy", secrets: [{ id, key, environmentVariable }] }`. Значения секретов не повторяй в ответе
  и не вставляй в файлы — они живут только в облаке.
- `ycDns { action, zone, name, type, value, ttl }` — записи DNS-зоны Cloud DNS. `records` — что уже есть,
  `add` — поставить значения для пары «имя+тип» (есть — заменит, нет — добавит), `delete` — убрать все значения
  пары. `zone` — имя или id зоны; без него работает, только если зона в каталоге одна. **Имя зоны при создании —
  домен БЕЗ точки** (`ycCreate { service: "dns", name: "example.com" }`), **имя записи — FQDN С точкой**:
  `www.example.com.`, а вершина зоны — само её имя `example.com.`. Тип: A, AAAA, CNAME, TXT, MX, NS, SRV;
  значение — строка или массив (для MX: `10 mx.example.com.`). `add` требует разрешения «создавать ресурсы»,
  `delete` — «удалять ресурсы». Обновление DNS в интернете расходится от минуты до часов — не жди мгновенной
  проверки через `checkUrl`, но сам адрес деплоя проверь.
- `ycRegistry { action, registry, image }` — образы Container Registry. `images` — что лежит в реестре
  (имя, теги, размер, `id`), `delete` — удалить образ **вместе со всеми его тегами** (необратимо).
  `registry` — имя или id реестра; без него работает, только если реестр в каталоге один. `image` — `id` образа
  (виден в `images`) или его тег. Чистить реестр нужно: каждая выкатка оставляет образ навсегда и он занимает
  платное хранилище. Но перед удалением спроси пользователя и не удаляй тег, на который ссылается работающий
  контейнер — после этого выкатка не соберётся (проверить, что работает: `ycContainer { action: "overview" }`).
  `delete` требует разрешения «удалять ресурсы». Удаление забирает теги: отдельно снять один тег инструмент
  не умеет — для этого нужна консоль облака.
- `ycStorage { action, bucket, key, file, content, prefix }` — файлы в бакете Object Storage. `list` — что лежит
  (можно `prefix` — «папка»), `upload` — положить файл (`file` — путь от рабочей папки) или готовый текст
  (`content`), `download` — забрать объект к себе (`to` — куда, по умолчанию имя объекта в рабочей папке),
  `delete` — убрать объект, `public` / `private` — открыть бакет для чтения из интернета и закрыть обратно.
  `bucket` — имя или id бакета; без него работает, только если бакет в каталоге один
  (создать: `ycCreate { service: "storage", name: "my-site" }`). `upload` требует разрешения «создавать ресурсы»,
  `delete` — «удалять ресурсы», `public` / `private` — «Разрешить агенту делать бакет публичным». Копирование
  файлов в бакете — не перенос, а загрузка. Тип содержимого ставится по расширению ключа: от него зависит,
  откроется картинка в браузере или скачается файл. **Открытый адрес объекта работает у других, только если у
  бакета включён публичный доступ на чтение** — иначе ссылка вернёт отказ; включить его можешь и ты, действием
  `public`. **Правило для `public`:** файлы бакета станет читать кто угодно из интернета, кто знает ссылку, и
  содержимое будет видно ПОИСКОВИКАМ, а не только людям с твоим доступом. Поэтому зови его только по ЯВНОЙ
  просьбе пользователя и не открывай так бакет с паролями, ключами и личными файлами — закрытые данные лежат
  в Lockbox (`ycSecret`). Публичность выключается обратно тем же инструментом (`private`), а из карточки бакета
  в панели «☁️ Cloud» — кнопкой.
- `ycDb { action, database, table, keys, item, key, limit }` — таблицы и записи ДОКУМЕНТНОЙ базы YDB
  (`ycCreate { service: "ydb", name: "app-db" }`, дальше работать с ней было нечем). `tables` — список таблиц,
  `create` — создать (`table`, `keys` — поля ключа, первый HASH, например `{ "id": "S" }`),
  `describe` — структура и число записей, `put` — положить запись (`item` — пары «поле → значение»,
  поля ключа обязательны), `get` — одна запись по `key`, `scan` — показать записи (`limit` до 100),
  `delete` — убрать запись по `key`, `drop` — удалить таблицу ВМЕСТЕ с записями (необратимо).
  `database` — имя или id базы; без него работает, только если база в каталоге одна. Значения полей
  передаются обычным JSON (строка, число, флаг, массив, объект) — типы API ставит сам.
  `create` и `put` требуют «Разрешить агенту создавать ресурсы», `delete` и `drop` — «…удалять ресурсы».
  Это только ДОКУМЕНТНЫЕ таблицы (Document API, DynamoDB-совместимые): обычные SQL-таблицы YQL этот интерфейс не обслуживает.
- `ycLogs { id, service, sinceHours, limit }` — логи ресурса за последние 3 часа (окно и лимит настраиваются).
  Читаются ВНУТРЕННИМ API приложения (Cloud Logging: лог-группы по REST, записи по gRPC с хоста `log-reading`) —
  внешний `yc` CLI для логов НЕ нужен, `ycInstall` не требуется.
- `ycInstall { force }` — официальный `yc` CLI внутрь папки приложения (`userData/bin`, системных прав не требует)
  и в PATH всех команд агента. Нужен, только если в песочнице требуется сама команда `yc`.
  Если `yc` ответит «The token is invalid» — повтори вызов через минуту: приложение продлевает IAM само.

## Контейнеры вглубь: `ycContainer`

Консоль YC показывает контейнер вкладками, и `ycContainer` повторяет их один в один.
Чтение доступно всегда; `deploy` / `rollback` / `update` требуют чекбокса
«Разрешить агенту менять контейнеры» (по умолчанию выключен).

```
ycContainer { action: "overview",  container: "<имя или id>" }
ycContainer { action: "revisions", container: "…", limit: 15, filter: "status=\"OBSOLETE\"" }
ycContainer { action: "revision",  container: "…", revisionId: "bba5…" }
ycContainer { action: "deploy",    container: "…", image: "cr.yandex/<registry-id>/<image>:tag", env: { "NODE_ENV": "production" } }
ycContainer { action: "rollback",  container: "…", revisionId: "bba5…" }
ycContainer { action: "update",    container: "…", name: "api", description: "Прод API", labels: { env: "prod" } }
```

- **overview** — статус, дата создания, URL, число ревизий и ПОЛНЫЕ настройки активной ревизии.
- **revisions** — список (id, статус, дата, образ, ресурсы). `★ активна` — та, что принимает трафик.
  `filter` принимает только поля `Revision.status` и `Revision.runtime`: `status="ACTIVE"`, `runtime="http"`.
- **revision** — детали одной ревизии.
- **deploy** — создать ревизию. Настройки берутся из активной ревизии, а всё переданное их переопределяет:
  `env` ДОБАВЛЯЕТСЯ к прежним переменным (`envReplace: true` — заменить набор целиком), `command`/`args`
  переопределяют ENTRYPOINT/CMD образа, `memoryMb` (кратно 128), `cores`, `timeoutSec`, `concurrency`,
  `serviceAccountId`, `networkId`, `minInstances`, `secrets` (Lockbox), `runtime: "task"`.
  **Образ, переменные и ресурсы меняются только новой ревизией** — «отредактировать работающий контейнер»
  в YC нельзя, редактор всегда заканчивается кнопкой «Создать ревизию».
- **rollback** — вернуть контейнер на старую ревизию (в консоли это «сделать активной»).
  Удалить ревизию нельзя: такого метода в API нет, есть только откат.
- **update** — имя, описание и метки самого контейнера (на запущенный код не влияет).

## Публичный вызов и логи

- Публичный вызов идёт по `URL` контейнера (виден в `overview`), но только если у сервисного аккаунта
  есть роль `serverless.containers.invoker` на каталог — это настраивает `ycDeploy { public: true }`.
- Логи ревизии: `ycLogs { service: "serverlessContainers", id: "<id контейнера>" }` (не ревизии).

## Токен и каталог

Подставляются автоматически: `YC_IAM_TOKEN` (свежий IAM-токен), `YC_CLOUD_ID`, `YC_FOLDER_ID`.
`yc init` не нужен.

## Ключи сервисов для ycList / ycCreate

`apiGateway`, `certificateManager`, `cdn`, `dns`, `logging`, `postbox`, `containerRegistry`, `iam`,
`lockbox`, `ydb`, `storage`, `serverlessContainers`, `vpc`.
