# Гайд по фронту ВК (vk.ru / vk.com) — проверенные методы

> Составлен и проверен в реальной работе: поиск людей, открытие профилей,
> диалоги, отправка сообщений, чтение истории переписок, анализ переписок.
> Все селекторы проверены на практике (аккаунт пользователя).

## 1. Базовые маршруты (URL)

| Действие | URL |
|---|---|
| Поиск людей по имени | `https://vk.com/search?c[section]=people&c[q]=ИМЯ+ФАМИЛИЯ` |
| Профиль по короткому имени | `https://vk.com/<shortname>` (например `jekochka19`) |
| Диалог по ID | `https://vk.ru/im/convo/<user_id>` (пример: `143668553`) |
| Список всех диалогов | `https://vk.ru/im` / `https://vk.com/im` |
| Главная / лента | `https://vk.com/feed` |
| Настройки | `https://vk.com/settings` |

**Важно:** `vk.ru` и `vk.com` взаимозаменяемы. Иногда редиректит на `al_im.php` —
это внутренний AJAX-роутинг ВК, надо просто подождать 2–5 сек и перечитать страницу.

### Где искать человека (проверено на практике)

1. **Сначала — поиск ВНУТРИ мессенджера.** «Поиск по чатам и сообщениям» находится в один клик от списка диалогов и ищет по истории переписок: если человек когда-то писал, он находится сразу, даже с закрытым профилем.
2. **Только потом — глобальный поиск людей** (`/search?c[section]=people`). У закрытых профилей он может не вернуть человека вовсе, зато вернуть десятки «рекомендаций» (однофамильцы, люди из того же города) — это НЕ результат поиска. Если в выдаче нет имени с нужной фамилией — считай, что поиск пуст, и не перебирай «рекомендации».
3. **Список диалогов ленивый:** в DOM одновременно ~15 чатов, остальные подгружаются прокруткой. Если человека нет в списке — он может быть ниже: `browserScroll { loadAll: true, container: "список диалогов" }`, затем `browserSnapshot`.

## 2. Ключевые селекторы (проверены на практике)

### Поле ввода сообщения — ГЛАВНОЕ
- ❌ НЕ `textarea` и НЕ `.im_editor` — там `contenteditable`-блок.
- ✅ **`[role="textbox"]`** — единственный стабильно работающий селектор.
- Заполнение: `browserFill(selector="[role=\"textbox\"]", text="...")`
  (при сбое приложение само переключится на способ insertText — клик + очистка + вставка).
- Отправка: `browserPress(key="Enter")` (Shift+Enter — перенос строки без отправки).
- ✅ Проверка отправки: `browserText` — ищем текст в истории диалога
  (сообщение появляется в конце переписки, рядом видно время отправки).

### Навигация
- Кнопка «Написать сообщение» в результатах поиска → сразу открывает диалог (минуя профиль).
- Кнопка «Сообщение» на странице профиля → открывает диалог.
- Список диалогов слева: элементы с текстом имени → `browserClick(text="Имя Фамилия")`.
- Кнопка «Открыть пост» → `text=Открыть пост`.

## 3. Подводные камни (реально встречались)

1. **Ленивая загрузка**: после `browserOpen` контент появляется через 2–5 сек.
   После каждого открытия — `browserWait` или повторный `browserText`.
2. **История диалога грузится долго**: «Загружается...» может висеть 5–10 сек.
   Иногда проще открыть диалог напрямую по URL `vk.ru/im/convo/<peer_id>`.
3. **Сессия слетает при закрытии браузера**: пользователь должен войти сам (QR или пароль).
   Войти за него нельзя — пароли выдумывать запрещено.
4. **Дубликаты имён в поиске**: всегда уточнять адресата (город/возраст/фото/«в друзьях»).
5. **Скриншоты обрезаются**: ВК рендерит очень много DOM-узлов. Для чтения
   состояния надёжнее `browserText`, скриншот — только для визуальной верификации.
6. **`browserText` отдаёт историю вместе с левым меню**: фильтровать по датам/именам,
   искать текст сообщений по имени собеседника и времени.
7. **Новые вкладки открываются БЕЗ сессии** — работать в существующей вкладке,
   не плодить новые. Закрывать только конкретные tabId, не «all».
8. **Поле ввода**: не использовать `textarea`-селекторы — в ВК их нет для сообщений.
9. **Список диалогов ленивый**: в DOM только ~15 видимых чатов, остальные подгружаются
   прокруткой — старый контакт «пропадает» из списка просто потому, что не догружен.
   Два пути: `browserScroll { loadAll: true, container: ".ConvoList__itemsWrapper",
   item: ".convo-item" }` (растёт по уникальным строкам, последняя прокручивается в кадр),
   затем `browserSnapshot`; или сразу данные — раздел 8 (`browserReplay`).
10. **История переписки ленивая**: старые сообщения (2021–2023) не отдаются в DOM, пока не
    догружены прокруткой вверх. Не листай вручную по одному экрану:
    `browserScroll { loadAll: true, how: "up", read: true }` — крутит, пока подгружается, и
    сразу отдаёт текст. Стикеры и картинки текстом не приходят — их видно только на скриншоте.
    Быстрее и полнее — replay запроса `messages.getHistory` (раздел 8).

## 4. Проверенный сценарий: отправить сообщение человеку

```
1. browserOpen("https://vk.com/im") — если браузер не открыт
   → если форма входа: пользователь входит сам (QR/пароль), агент ждёт
2. browserOpen("https://vk.com/search?c[section]=people&c[q]=Имя Фамилия")
3. browserText → смотрим результаты (имя, город); уточнить у пользователя, если дубликаты
4. browserClick("text=Написать сообщение") → открывается /im/convo/<id>
   (или browserClick("text=Имя Фамилия") → профиль → browserClick("text=Сообщение"))
5. browserWait 2–5 с → browserText → подтвердить, что диалог открыт
6. browserClick(selector: "[role=\"textbox\"]")
7. browserFill(selector: "[role=\"textbox\"]", text: "текст сообщения")
8. browserPress(key: "Enter")
9. browserText → проверить, что текст сообщения появился в истории ✅
   (не видно → повторить шаги 6–8)
```

## 5. Проверенный сценарий: анализ переписок

1. Открыть `vk.ru/im` (список диалогов), подождать 3–5 сек.
2. `browserText` — список диалогов виден как имена в левом меню.
3. Открыть диалог: клик по имени в списке ИЛИ напрямую `vk.ru/im/convo/<peer_id>`.
4. Прочитать `browserText` (~15 000 симв.) — обычно хватает на суть.
5. Если «Загружается...» — подождать 5 сек, перечитать; если не грузится —
   открыть URL напрямую с peer_id из параметров ссылки.
6. Длинную историю читать `browserScroll { loadAll: true, how: "up", read: true }` — она
   сама прокручивает вверх, пока подгружаются старые сообщения, и отдаёт текст. Если в ответе
   «упёрся в предел N шагов» — вызвать ещё раз (продолжит с того же места), пока не появится
   «это конец списка».
7. Проанализировать по методологии agent-guide:chat-analysis: тип отношений,
   темы, суть; составить таблицу.

## 8. Быстрое чтение данных: replay запроса веб-клиента (замер 15.09.2026)

**Главное:** список диалогов и история НЕ читаются из DOM надёжно — виртуализация
переиспользует узлы, часть строк не отрисована, а `ref` устаревают после перерисовки.
Зато веб-клиент САМ ходит за этими данными запросом. Повторяем ЕГО запрос из самой
страницы (куки и CORS такие же, как у клиента) и листаем ответ курсором.

Что подтвердил живой замер на `vk.com/im`:

| Параметр | Факт |
|---|---|
| Эндпоинт | `POST https://api.vk.ru/method/messages.getItems` |
| Версия | `v=5.285` — ВНУТРЕННЯЯ версия клиента, брать ТОЛЬКО из перехвата (свои 5.95/599 сервер отвергает ошибкой 100 `invalid v`) |
| Тело | форма: `v, client_id, start_from=conversations_<id>, filter=all, target_count, extended=1, access_token=…` (токен в ТЕЛЕ, не в query) |
| Ответ | `response.conversations.items[]` + `total_count`, курсор — `last_item` |
| Следующая страница | `start_from=conversations_<last_item>` |
| Конец | `items.length == 0` или собрано `total_count` |
| DOM, если всё-таки нужен | контейнер `ConvoList__itemsWrapper`, строки `.convo-item` (`#im_dialogs` и `.nim-dialog` в текущем DOM НЕ существуют) |

Рабочий порядок (проверен: 2–3 вызова вместо 7–8 ходов «прокрутил → снял карту»):

```
1. browserOpen("https://vk.com/im") — клиент сам делает первый запрос списка
2. browserNetwork { since: false } — в журнале видно POST …/messages.getItems:
   адрес с v=5.285, тело с токеном (секреты скрыты), ответ сервера
3. browserReplay { match: "messages.getItems", cursorParam: "start_from",
                   cursorPrefix: "conversations_", maxSteps: 40 }
   — повторяет тот же запрос ИЗ СТРАНИЦЫ, листает курсором, кладёт items[] в ФАЙЛ
4. readFile(path из ответа) — дальше разбор своим кодом (или pick-поля в самом вызове)
```

История переписки — та же схема: открыть `vk.ru/im/convo/<peer_id>`, прокрутить вверх
(клиент сам запросит следующие сообщения), затем `browserReplay { match: "messages.getHistory" }`
с `cursorParam` из перехвата.

Грабли, на которых уже спотыкались:

- **Не подставляй `v` руками** — это полчаса на ошибку 100 `invalid v`. Версия и токен
  берутся из перехвата.
- **Токен не «вытаскивай»** в текст — replay повторяет запрос внутри страницы, где сессия
  и так на месте.
- **Пагинация курсорная** (`start_from=conversations_<id>`), а не `offset`.
- **Накопленное — в файл** (`save: true` у browserReplay и browserEval), а не в `window.__var`:
  перезагрузка вкладки стирает переменные, файл остаётся.
- **Прокрутка «на глаз» проскакивает строки.** Если читаешь список всё-таки по DOM, укажи
  селектор СТРОКИ: `browserScroll { loadAll: true, container: ".ConvoList__itemsWrapper", item: ".convo-item" }`
  — тогда рост считается по уникальным строкам, а последняя прокручивается в кадр (это
  движение и запускает подгрузку).
