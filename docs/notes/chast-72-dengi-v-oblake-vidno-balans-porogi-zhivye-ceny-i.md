## Часть 72: деньги в облаке видно — баланс, пороги, живые цены и «хвосты» в рублях (`yc-billing.js`)

**Зачем.** Про деньги приложение умело только одно: назвать цену ДО создания ресурса (`yc-costs.js`). А два вопроса,
которые человек задаёт сразу после, оставались без ответа — «что с моим счётом» и «за что я плачу, хотя мне это
уже не нужно» — и человек шёл за ними в чужую консоль. При том что половина ответа лежит в том же облаке, куда у
приложения уже есть доступ.

**Что сделано.**
- `src/yc-billing.js` — модуль биллинга (чистый Node, без Electron): платёжные аккаунты и баланс, пороги-бюджеты,
  каталог услуг и КАТАЛОГ ЦЕН (SKU) с настоящими ценами, поиск цены по словам и «платные хвосты» в рублях за месяц.
  Плюс мелочи, без которых ответ бесполезен: печать денег с разрядами и валютой аккаунта, разбор трёх видов бюджета
  (расход / потребление / остаток), выбор ДЕЙСТВУЮЩЕЙ версии цены по времени вступления в силу, пометка ступенчатой
  и договорной цены, объяснение кодов 403/404 словами.
- Главное знание, которое нельзя потерять при правке: **РАСХОДА в REST API НЕТ**. В Billing API живут только
  платёжные аккаунты (активность, валюта, БАЛАНС), бюджеты (ПОРОГИ, после которых приходит письмо), каталог услуг
  и каталог SKU с ценами. Детализация расходов — только в консоли (Биллинг → Расходы) и в выгрузке в бакет. Поэтому
  модуль говорит это прямо и НИКОГДА не выдумывает сумму счёта: на «сколько я потратил» честный ответ — «точных цифр
  по API нет, вот баланс, пороги и то, за что платят по факту».
- Что важно помнить про сам биллинг: он привязан к ПЛАТЁЖНОМУ аккаунту, а не к каталогу (`folderId` нужен только
  хвостам), требует роли `billing.viewer`, и без неё приходит 403 — это самая частая причина «биллинг не работает»,
  поэтому отказ объясняется словами, а не показывается сырым. Несколько платёжных аккаунтов без ссылки НЕ
  угадываются: показать чужие деньги хуже, чем спросить. Баланс — это не расход: минус и ноль названы прямо, потому
  что это единственный честный сигнал «облако скоро остановит ресурсы». Порог-бюджет — предупреждение, а не счёт, и
  создать его по API нельзя без id пользователя для уведомлений (отправляем в консоль, а не угадываем).
- **Хвосты считаются в ОДНОМ месте.** «Что такое платный хвост» решает Compute (`paidLeftovers`), биллинг берёт это
  правило готовым (ему передаются `ycCompute` и `ycVpc`) и добавляет то, чего Compute не видит: остановленные машины
  (их диски платят всегда — это ответ на «почему счёт не упал до нуля»), снимки старше 90 дней и работающие машины —
  текущий счёт, а не мусор. В каждой строке: что это, СКОЛЬКО в рублях за месяц и что делать. Хвосты остаются видны,
  даже когда биллинг недоступен: они читаются правами каталога, и падение биллинга не имеет права прятать отчёт о
  деньгах.
- **Две настоящие ошибки найдены и починены.** ① Цена диска считалась по БАЙТАМ: размер из API приходит в байтах, а
  тариф `diskMonth` считает за гигабайт — «диск 100 ГБ» оценивался в **371 миллиард рублей в месяц**. Ошибка жила в
  двух местах инструмента машин (`ycCompute: disks` и `leftovers`) и попадала человеку прямо в ответ; теперь байты
  переводятся в одном месте (`GB` в биллинге и `/ 1073741824` в инструменте), рядом с `diskMonth` написано, что
  аргумент — гигабайты, а набор биллинга стережёт это статически. ② Хвост называл размер, но не имя объекта («диск
  100 ГБ», «снимку 120 дней») — по такому отчёту нельзя ничего почистить; теперь и диск, и снимок названы.
- **Попутная находка в роутере (важно для следующих блоков).** Схемы группы «облако» доросли до ~11 250 токенов, и
  политический потолок схем (`ROUTER_MAX_TOKENS` = 16 500) перестал вмещать базу (6 948) вместе с группой: сказав
  «подними мне сервер в яндекс облаке», человек не получал НИ ОДНОГО облачного инструмента — группа режется целиком.
  Потолок поднят до **23 000** («база + 1–2 большие группы»: самая большая группа вместе с базой помещается — 18 198),
  а правило из части 71 (уже включённые группы режет только окно) осталось. Проверено на окнах 32k/60k/200k.
- Набор `test/yc-billing.test.js` — **21 проверка** (в цепочке `npm test`): `[1]` единицы без сети (деньги, валюты,
  пороги, действующая цена, ступени, поиск по словам), `[2]` НАСТОЯЩИЙ модуль против локального HTTP-сервера с
  настоящей машиной состояний и НАСТОЯЩИМИ модулями машины и сети (хук `AI_AGENT_YC_BASE`) — каталог цен читается
  страницами, «несколько аккаунтов без ссылки» — отказ, 403/404 объясняются словами, цена каждого хвоста сверяется с
  тарифами `yc-costs.js` поштучно, недоступный биллинг не прячет хвосты, «только чтение» проверяется по факту (ни
  одной изменяющей операции); `[3]` инструмент агента (внятные отказы, обзор, цена, хвосты, пороги); `[4]` проводка
  (канал `yc:billing`, мост, схема, группа «облако», промпт, права, справочник, сторож smoke, цепочка `npm test`).

**Чего в этой части НЕТ и почему.** Агент по-прежнему ничего не меняет в деньгах: в Billing API изменяющих методов нет
вовсе, а порог-бюджет требует id пользователя для уведомлений. Поэтому «поставить лимит» — это инструкция человеку
(консоль → Биллинг → Бюджеты), а не действие агента. Биллинга нет и в списке услуг дашборда (`SERVICES`): это не
создаваемый ресурс каталога, а раздел про счёт, и у него свой канал и свой инструмент.
