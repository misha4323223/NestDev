## Часть 40, заход 4.1: находка закрыта — таймаут гасит ДЕРЕВО (src/shell-tools.js)

Фикс ровно по плану из захода 4: `runTerminalCommand` переведён с `execFile` на `spawn` со своей
группой процессов, сторож — с подмены `execFile` на подмену `spawn`.

**Что стало в модуле.**

- `spawn(sh.shell, sh.args, { cwd, windowsHide, env: commandEnv(command), detached: <не Windows>,
  stdio: ["ignore", "pipe", "pipe"] })`. `detached` — это и есть условие, по которому сигнал уходит
  ГРУППЕ, а не одной оболочке. `stdin: "ignore"` убирает вторую засаду: «cat» без этого ждал ввода
  до самого таймаута.
- `killCommandTree(child)` — тот же приём, что в фоновых процессах (`killProcessTree`/`bgKill`):
  на Windows `taskkill /pid <pid> /T /F`, на POSIX `process.kill(-pid, "SIGTERM")` и догоняющий
  `SIGKILL` через 1.2 с, в конце `child.kill()`. Вынесен в зависимость (`deps.killTree`) — как
  `killPid` у фоновых процессов: иначе сторож не может проверить ветку таймаута, не посылая
  настоящих сигналов выдуманному pid.
- Таймер свой: по `<timeoutMs || 120000>` гасим дерево; если оболочка почему-то не умерла, ответ
  отдаётся через 1.5 с всё равно. Таймер намеренно НЕ `unref`: обещание обязано разрешиться,
  иначе инструмент агента повиснет навсегда.
- Предел вывода (32 МБ, вместо `maxBuffer`) теперь наш: за пределом команда останавливается деревом
  и говорит об этом честно, а накопленное выбрасывается (в ответ всё равно уедет только начало).
- Тексты ответов агента не изменились (`Команда завершилась с кодом таймаут (N с):`, части
  stdout/stderr по 3000 знаков, подсказка оболочки, `[stderr]`). Добавилось два честных случая:
  смерть от чужого сигнала («Процесс завершён сигналом SIGSEGV.») и отказ без вывода («Вывода нет —
  команда завершилась молча.»).

**Сторожа (`test/shell-tools.test.js`).** Поддельный `spawn` возвращает поддельный ПРОЦЕСС: потоки и
события как у настоящего (`error` + `close` при ENOENT, `close(code, signal)`; `code: null` — это не
ноль). Добавлено: своя группа (`opts.detached`), `stdio`, таймаут гасит дерево, ответ при зависшем
процессе приходит меньше чем за 3 с, предел вывода останавливает команду — и главное: **настоящий
процесс** (команда с ребёнком, таймаут, проверка `process.kill(pid, 0)`). Это единственная проверка,
которая ловит исходный баг: подмена `killTree` её обходит.

**Контроль.** `detached: false` (то есть ровно баг) ловят: набор — двумя проверками, включая
настоящую («после таймаута ребёнок оболочки жив (PID …)»), и живой прогон —
«❌ детей оболочки не осталось: живо 1». Файл возвращён, `sha256` совпал (`38033e6c…`).

**Живой прогон.** `test:live:tools-run` — **46 ✅ / 0 ❌**: прежнее измерение-находка стало настоящей
проверкой («после таймаута runCommand детей оболочки не осталось»), с ожиданием догоняющего SIGKILL.

**НАЙДЕНО ПОПУТНО (не исправлено, следующий кандидат).** Та же болезнь есть у `runCapture`
(`src/deploy-ipc.js`, строки ~56–80): там тоже `execFile(sh.shell, sh.args, { timeout, maxBuffer })`,
то есть команды деплоя (сборка, npm, docker) запускаются без своей группы процессов — по таймауту
оболочка гибнет, а её дети живут и держат порт. Фикс тот же (`spawn` + `detached` + `killProcessTree`),
цена та же: сторож деплоя построен на подмене `execFile`. Остаток того же класса, но ниже риском —
`system-stack.spawnRaw` (ставит пакеты, 60 с) и `paths-git.runGit` (прямой `git`): там дети портов
обычно не держат, но это надо проверять отдельно, а не верить на слово.

### Там же, полным прогоном живых: две оглохшие прогонки (найдены и исправлены)

Пока прогонялись только «свои» живые прогоны, две штуки молчали сломанными с захода 2:
`test:live:projects` (`scripts/live-projects-preview.js`) и `test:live:run-ipc` (`scripts/live-run-ipc.js`).
Оба подменяют `electron` и перехватывают `require` по ПОДСТРОКЕ:
`if (t.indexOf("agent-tools") >= 0) { … return { createAgentTools } }`. Пока в доме был один
`agent-tools.js`, это работало. После дробления та же подстрока стала матчить и `agent-tools-git.js`,
и прогон получал «{ createAgentTools } без createGitTools» → падение
«TypeError: createGitTools is not a function» ещё до первой проверки.

Исправлено точно: `if (/agent-tools\.js$/.test(t))` — перехват только САМОГО сводного модуля.
Оба прогона после правки зелёные (`projects` — все проверки, `run-ipc` — все проверки).

**Сторож на этот класс (новый, в `test/repo-shape.test.js`).** По всем `scripts/live-*.js`
собираются подстановки вида `indexOf("…") >= 0`; если такая подстановка совпадает с именами
ДВУХ и более файлов в `src/`, это отказ с названием файла и списком проглоченных модулей.
Подстановки, не совпадающие ни с одним именем файла (поиск по тексту), не в счёт. Контроль:
вернуть широкую подстроку в `live-run-ipc.js` — сторож краснеет и называет все шесть модулей
(`agent-tools-cloud/files/git/run/write.js`, `agent-tools.js`).

**Урок (в HANDOFF, §4):** живые прогоны надо гонять ЦЕЛИКОМ. Ни набор, ни сторож дома в них
не смотрит, поэтому сломанный живой прогон — это не «одна красная строчка», а ПОТЕРЯННЫЙ
сторож: он молчит и выглядит рабочим.
