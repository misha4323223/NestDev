## Часть 61: у каждой роли — своя папка, а в ней PROMPT.md (по каждому проекту)

**Зачем.** Роль чата (Разработчик / Ассистент / Менеджер / Исследователь) — это РЕЖИМ: её текст
зашит в код и одинаков у всех. А человеку нужно своё — тон, правила, знание о бренде. Раньше выбор
был плохой: бриф в README (уходит ВСЕМ режимам) или «прочитай файл» руками каждый раз.

**Что сделано.** Настройки → новая вкладка «🎭 Роли»: у каждой роли — своя папка, и у КАЖДОГО
проекта она своя (`settings.roleDirs = { <id проекта>: { dev, assistant, manager, researcher } }`).
Из папки читается файл `PROMPT.md` и дописывается в системный промпт — сразу после текста роли и
ДО «САММАРИ ПРОЕКТА»: `SYSTEM_PROMPT + roleNote + roleFolderNote + mismatchNote + …`.

- Новый модуль `src/role-folders.js` (чистый: fs/path снаружи, без зависимостей): чистка раскладки,
  поиск файла по вариантам имени, чтение с обрезкой С ДВУХ КОНЦОВ (потолок 8000 символов + маркер),
  сборка блока. Любая ошибка чтения — пустая строка, НЕ исключение: прогон не имеет права падать.
- Папка не задана (или файла нет) → `roleFolderNote === ""`, промпт не меняется ни на байт.
- Папки принадлежат ПРОЕКТУ (ключ — id проекта, а не путь): переименование/переезд привязку не рвёт.
  Глубокую чистку делает `role-folders.js` при чтении — одна точка правды, без второго списка ролей.
- Телефон (мост) работает: его прогон идёт в главном процессе (app.js: `isElectron = !!api`, а
  mobile-api.js ставит `window.api`), значит блок роли он получает так же, как настольное окно.
  Системный диалог выбора папки телефону ЗАКРЫТ (mobile-bridge) — кнопка 📂 там тихо говорит
  «впиши путь вручную» вместо ошибки.
- Веб-превью БЕЗ моста (`server.js`) диск ПК прочитать не может — это ограничение браузера, а не
  настройки: поля ролей там видны, но подхватывать файл нечему (нужен был бы fs-эндпоинт сервера).

**Проверки.** Новый набор `test/role-folders.test.js` (15 проверок: чистка раскладки, папка активного
проекта, чтение PROMPT.md с BOM/CRLF/обрезкой, отказы вместо падений, блок в промпт, совпадение
списка ролей с ядром, живая запись/чтение `roleDirs` в настоящем хранилище, проводка main→прогон,
