## Часть 65: фолбэк удалённого playwright — в репозитории (backup-playwright/)

**Зачем.** Раньше фолбэк удалённого Playwright (`backup-playwright/`: снимки `package.json`,
`package-lock.json`, `electron-builder.yml`, `restore.js` и описание) лежал ТОЛЬКО на диске: каталог
был внесён в `.gitignore`, и в любом другом клоне вернуть Playwright было нечем. Теперь каталог
В РЕПОЗИТОРИИ — вернуть браузерный драйвер можно из любого клона, а не с одной машины.

**Что сделано.**
- `.gitignore` — правило `backup-playwright/` убрано (остался комментарий, почему каталог держим
  в репозитории). OTA-исключения `!ota/manifest.json` / `!ota/bundle.json` на месте.
- `backup-playwright/restore.js` переписан БЕЗ перезаписи файлов снимками. Прежняя редакция копировала
  `package.json.bak` → `package.json` целиком, то есть затирала всё, что накопилось в `package.json`
  после удаления playwright (новые скрипты и тесты). Новая: `package.json` — ДОБАВЛЯЕТ строку
  `"playwright": "<версия>"` в `dependencies` (версия — из снимка, единый источник правды);
  `electron-builder.yml` возвращается из снимка ТОЛЬКО если из него пропали исключения `asarUnpack`
  для playwright; лок и `node_modules` ставит `npm install --ignore-scripts` (снимок лока для этого
  больше не нужен, файл оставлен справочно). Появились флаги `--dry-run` (план, ничего не менять) и
  `--help`.
- `backup-playwright/README.md` — описание приведено к правде: каталог в репозитории, поведение
  `restore.js` безопасное, есть `--dry-run`.
- `scripts/live-project-brief.js` — устаревший комментарий («в репозиторий не едет») поправлен.
- `test/repo-shape.test.js` — +2 проверки: каталог не под `.gitignore`, его файлы на месте и
  `playwright` НЕ вернулся в зависимости; `restore.js` не копирует снимки поверх и отвечает на
  `--dry-run`. Набор 12 → **14**.

**Грабли.** «Фолбэк» и «снимок целиком» несовместимы: снимок стареет с первой же правкой
`package.json`, а восстановление снимка молча стирает свежую работу. Поэтому фолбэк должен
ДОБАВЛЯТЬ недостающее, а не заменять файл. И ещё: каталог теперь участвует в обходе структуры
(`project-brief`), поэтому в `live-project-brief.js` по-прежнему важно сверять ИМЕНА ЗАПИСЕЙ, а не
подстроку во всём тексте — иначе `node_modules` из `.bak`-снимка краснит чужой проверкой.
