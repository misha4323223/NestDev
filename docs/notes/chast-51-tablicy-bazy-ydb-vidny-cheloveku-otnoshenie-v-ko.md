## Часть 51: таблицы базы YDB видны человеку — отношение в консоли облака (✅ сделано)

**Задача (продолжение «облака руками агента»).** Часть 50 дала базу YDB агенту
(`ycDb`) — а человек в карточке базы панели «☁️ Cloud» не видел ничего. Полка
самая настоящая (serverless-база создаётся ровно ради данных), но её содержимое
было только у модели. Довести до конца: таблицы должны быть видны в консоли.

**Почему не консольный API.** Таблиц YDB в консольном API нет — они живут в HTTP
Document API САМОЙ базы, и адрес у каждой базы свой (`documentApiEndpoint`: у
serverless и выделенных баз хосты разные), поэтому по памяти он не собирается.
Отношение «Таблицы» помечено в `src/yc-console.js` флагом `docApi`, и
`relationList` по нему сначала находит базу в каталоге (`findDatabase` по имени
или id), а потом спрашивает таблицы её же Document API — тем же слоем
`src/yc-db.js`, что и инструмент агента. Человек видит честный путь:
«Document API <адрес базы> ListTables».

**Что сделано.** Отношение `ydb.tables` («📋 Таблицы», `listKey: tables`),
столбец `name` в карте колонок и ветка `rel.docApi` в `relationList`. Если база
не нашлась (удалили, пока карточка была открыта), карточка ОБЪЯСНЯЕТ это
словами, а не показывает пустой список. Новых каналов не понадобилось: всё идёт
прежним путём `yc:console:list` → `relationList`, поэтому `preload.js` и список
разрешённого у телефона не тронуты.

**Сторожа.** `test/yc-db.test.js` вырос 20 → **23**: отношение проверяется по
исходнику (ветка `docApi`, столбцы, «Таблицы»), плюс негативный контроль — у
отношения убрали `docApi`, набор покраснел, файл возвращён, sha256 сошёлся.
`test/smoke.test.js` понимает новую ФОРМУ запроса отношений (`docApi`) и не
считает её запросом в консольный API.
