**НАХОДКА (исправлена): `.tar.gz` уезжал в unzip.** Живой прогон скачал с СВОЕГО сервера настоящий
`.tar.gz` со стандартным типом `application/gzip` — и получил «Не удалось распаковать (нужен unzip)».
Причина: `downloadAndExtractTo` решал формат через `contentType.includes("zip")`, а «gzip» СОДЕРЖИТ «zip».
URL при этом явно кончался на `.tar.gz` — но проверка типа шла первой. Набор этого не видел, потому что
проверял текст вызова, а не решение. Исправлено выносом чистой функции `archiveKind(url, contentType)`
(имя файла решает первым, тип — только подсказка, `«gzip» — это НЕ zip`), она экспортируется наружу и
сторожится набором: таблица случаев (10 пар имя/тип) + настоящая распаковка `.tar.gz` с локального сервера.
Флаг `-z` для tar теперь ставится и по типу — иначе настоящий gzip без имени `.tar.gz` не распакуется.

**Живой прогон `npm run test:live:tools-net` — 35 ✅ / 0 ❌.** Поднимается настоящий `main.js` и
НАСТОЯЩИЙ локальный HTTP-сервер (порт выбирает система): JSON-эхо запроса с заголовками, HTML-страница,
сжатый tar-архив (собран в прогоне через zlib, не скачан извне), не-архив, 404. Проверено по делу:
`checkUrl` — 200 с типом и размером тела, 404 кодом, закрытый порт объяснён, адрес без схемы отвергнут,
адрес облачных метаданных НЕ отдан как успешный ответ; `checkPort` — живой порт «занят», порт 1 «свободен»,
негодный номер отвергнут; `listPorts` — наш слушатель ВИДЕН в настоящем списке; `apiRequest` — POST с

**Две неверные пробы (мои, не инструмента).** (1) Заголовок `X-Прогон: да` — fetch справедливо отказывает
заголовкам с кириллицей, проба падала из-за себя; заменена на ASCII и заодно усилена: сервер теперь
отдаёт все полученные заголовки, и видно, что свой заголовок доехал. (2) Требование «папки не осталось»
после неудачной распаковки — папка остаётся пустой, и это не мусор: проверяем отсутствие ФАЙЛОВ.

**Контроли.** (1) Вернуть исходную логику (`contentType.includes("zip")` первым) — ловят ОБА сторожа:
набор на таблице решений («'tar' !== 'zip'»), живой прогон на деле («Не удалось распаковать (нужен unzip)»).
(2) Заставить `checkPort` всегда отвечать «свободен» — набор не ловит (0 падений), живой прогон ловит
(«наш живой порт N назван занятым»). Оба файла возвращены, `sha256` совпали.
