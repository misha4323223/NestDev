## Фаза поиска ошибок, находка 1: отказ браузера больше не выглядит успехом

Закрывает две записи «НАХОДКА (не исправлено, записано)»: заход 11 (`vaultFill`) и заход 13
(`browserOpen` и подсказка справочника). Это одна болезнь: отказом считался только ответ,
начинающийся с «Ошибка», а настоящий набор отказывает иначе — «Браузер не запущен. Сначала
вызови browserOpen (url).», «Вкладка не найдена: …». Замер на неисправленном коде (живой прогон
`test:live:tools-vault`): при ЗАКРЫТОМ браузере `vaultFill` отвечал «OK — логин и пароль для
«Спуник» подставлены в форму (пароль в чат не выводится)» — агент считал вход выполненным,
хотя форма не заполнялась; `browserOpen` так же приклеивал к отказу «📘 По этому сайту есть
справочник агента …» — агент мог решить, что страница открылась.

**Починка.** Список отказов один и живёт в `browser-tools.js`: `stepFailed` переименован в
`isBrowserFailure` (тот же список `Ошибка|Не нашёл|Браузер не запущен|Вкладка не найдена|browserDOM:`)
и отдаётся НАРУЖУ. Им пользуются `browserAct` (как и раньше — остановка цепочки), `browserOpen`
(`src/agent-tools-browser.js`) и `vault.fillLogin` (`src/vault.js`, helper `browserRefused`).
Стенды со своей заменой набора (старые `bt`-двойники без `isBrowserFailure`) получают прежний
узкий признак `/^Ошибка/` — поведение двойников не меняется, а приложение всегда ходит с
настоящим набором.

**Сторожа (краснели ДО починки — контроль снят на неисправленном коде).**
`test/smoke.test.js`: в теме «браузер агента» настоящий отказ набора (пять текстов) признаётся
отказом, два успеха — нет, и к отказу подсказка не приклеивается; в теме `vault` — `fillLogin`
с настоящим `isBrowserFailure` не выдаёт отказ за подстановку (и не «отправляет» форму, и не
называет пароль). Живые прогоны: `test:live:tools-browser` — **77 ✅ / 0 ❌** (`isBrowserFailure`

`test:live:tools-vault` — **27 ✅ / 0 ❌** (отказ назван честно, успеха нет, пароль не утёк).
Контроль на неисправленном коде: smoke — 530 прошло / 2 упало; живой vault — 2 красных с
