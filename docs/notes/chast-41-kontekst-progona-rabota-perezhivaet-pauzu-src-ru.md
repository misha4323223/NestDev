## Часть 41: контекст прогона — работа переживает паузу (src/run-context.js)

**Жалоба человека:** «если я нажал на паузу, чтобы агент продолжил с того же места, а не искал, чем он занимался». Причина нашлась точная и до этого не измеренная ни одной проверкой.

**Что было не так.** Рабочая история — ответы агента с вызовами инструментов и ИХ РЕЗУЛЬТАТЫ — живёт внутри прогона и вместе с ним выбрасывается. В новый прогон уходят одни тексты реплик: окно фильтрует `role:"tool"` (`src/renderer/chat-send.js`), а сводка состояния работы есть только при включённой долгой работе (миссии). Итог: после паузы модель не знала ни одного факта своей работы — перечитывала файлы, повторяла команды, спрашивала «а что уже сделано». Пауза, «Стоп» и закрытие приложения теряли всё одинаково.

**Что сделано.** Новый модуль `src/run-context.js` (320 строк) — чекпоинт рабочей истории на диске, рядом с проектом: `.agent/runs/<чат>.json` (папка `.agent` целиком исключена из git через свой `.gitignore`). Модуль чистый: путь, чат и разбор пар приходят значением/функцией, диска и `fs` он не достаёт сам.

- **запись** — ДО запроса к модели и ПОСЛЕ выполнения инструментов (и пачкой, и строгой очередью). Обрыв на любом шаге оставляет работу на диске, а не в памяти;
- **возврат** — `planResume` (чистая функция, без диска): опора — последняя реплика человека, которая ЕСТЬ в чекпоинте; всё, что в окне после неё (обрывок ответа, новая просьба), дописывается в конец. История не удваивается;
- **отказы подклеивать наугад**: окно, которое не узнаётся в чекпоинте, и чекпоинт, записанный для ДРУГОЙ рабочей папки, не подхватываются;
- **обрезка**: шаг — «начало 4000 + пометка + хвост 1500» (у вывода команды ошибка обычно в хвосте), картинки в чекпоинт не идут (base64 — это мегабайты на шаг), тексты перед записью проходят маскировку секретов (`redactSecrets`), потолок файла 512 КБ лечится отбрасыванием старых шагов, а не отказом от записи;
- **хвост без результатов снимается** (`dropDanglingCalls`): `assistant` с `tool_calls`, на который не пришло ни одного `tool`, провайдер отвергает 400;
- **`close()`** на обычном финале: сданная работа в контекст не возвращается, иначе агент «продолжал» бы то, что уже сделано. Пауза и «Стоп» чекпоинт оставляют.

**Проводка.** `main.js` отдаёт модуль прогону (2 строки). В `run-ai.js`: `dir` — ФУНКЦИЕЙ (рабочую папку меняет клонирование и смена проекта), `id` — из живого значения прогона, `sanitizeToolPairs` — живой разбор. В сборке запроса теперь сохраняются `tool_calls` и `tool_call_id` — без них разбор пар выбрасывает результат как осиротевший, и продолжение снова пустое (это и была главная тихая ошибка всей затеи).

**Проверки.** `test/run-context.test.js` — **16** (новый набор, настоящая файловая система во временной папке: обрезка 512 КБ, маскировка секретов и атомарная запись подделкой `fs` не проверяются). Стенд прогона `test/run-ai.test.js` — **27** (+2: работа возвращается в ПЕРВЫЙ же запрос вместе с `tool_call_id`, финал закрывает чекпоинт, а пауза — нет; плюс сверка проводки). Живой прогон `test:live:run-context` — **36 ✅ / 0 ❌** на настоящем `main.js` с подменённым провайдером: остановленный прогон оставил работу на диске (результат настоящего инструмента, свой `tool_call_id`), второй прогон получил её в первом же запросе и не потратил раунд на повторное чтение, обычный финал чекпоинт убрал, чужой чат чужую работу не подхватил. Сторожа: `backendSrc` + оба `scanWiring` знают модуль, в `smoke.test.js` — новая тема «контекст прогона: работа возвращается в следующий прогон, а не ищется заново».

**Негативные контроли — 11/11**, файлы возвращены байт в байт по sha256. Пять ловятся только набором модуля, шесть — набором прогона и/или живым прогоном.

**Находка в моей же проверке.** Контроль «чекпоинт другой рабочей папки» не поймала НИ ОДНА проверка. Причина: проверка №4 набора проверяла чужую папку, в которой чекпоинта просто НЕТ, — то есть проходила вхолостую, а поле `dir` внутри файла не проверялось ничем. Дописано настоящее «проект скопировали/переименовали»: файл чекпоинта лежит в новой папке, внутри записана СТАРАЯ. Урок в копилку: проверка «в другой папке не подхватилось» обязана утверждать, что файл там ЕСТЬ (иначе она про отсутствие файла, а не про сверку папки).

**Версия и набор.** 1.5.209 → **1.5.210**; `node scripts/make-ota.js --unsigned` (набор **1.5.214**, без подписи — ключ владельца ещё не заведён).
## Находка того же захода: живой прогон окна был мёртв с момента работ по TLS (test:boot)

`npm run test:boot` падал на первом же шаге: `fetch failed … ECONNREFUSED 127.0.0.1:9187`.
Причина не сетевая: после работ по безопасности мобильный мост без сертификата больше НЕ
поднимается — `MobileBridge.start()` выходит, если `prepareTls()` не дал сертификата, а
`certDir` без явной папки пуст («Не задана папка для сертификата»). А `scripts/live-boot.js`
строил мост как `new MobileBridge({ handlerMap: new Map() })` — без `certDir` — и ждал ответы
по обычному `http://`. Значит, единственная проверка, которая собирает окно из тегов
`index.html` в браузерной песочнице (в песочнице нет libglib для Chromium, поэтому `test:live`
там не идёт), не проходила вовсе — и это никем не сторожилось.

**Починено в том же заходе** (продуктовый код не тронут — только сам прогон): он заводит
временную папку для сертификата, поднимает мост НАСТОЯЩИМ путём телефона (https,
самоподписанный сертификат), первым делом проверяет сам факт подъёма (`b.server` и `b.tls` —
иначе был бы молчаливый пустой сервер без ответов), тянет каждый файл разметки по https и
отдельно проверяет обещание безопасности: **по открытому HTTP окно не отдаётся**.

- `test:boot` — **211 проверок, 0 падений** (было: падение на шаге [1]);
- негативные контроли `--strip=` на настоящих модулях поймали **3 из 3**: `agent-core.js` — 4 падения, `chat-send.js` — 30, `context-window.js` — 30;
- замечание: `--strip=bootstrap.js` контролем НЕ ловится, и это честно — файл лишь дублирует
  подключение охраны полей ввода (её сторожит `test/field-guard.test.js`); снимаешь настоящий
  модуль — прогон падает.

Урок в копилку: **проверка, которая не запускается, выглядит как проверка, которая проходит.**
Живой прогон умирает молча, если его вход (`start()` моста, порт, путь) перестал быть верным;
поэтому у переписанного шага [1] теперь есть сторож самого подъёма, а не только ответов.
