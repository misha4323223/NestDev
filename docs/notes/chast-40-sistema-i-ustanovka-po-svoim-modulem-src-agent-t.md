## Часть 40, заход 5: система и установка ПО — своим модулем (src/agent-tools-system.js)

Девять обработчиков уехали из `agent-tools.js` в `src/agent-tools-system.js` (342 строки):
`getSystemInfo`, `installSystemPackage`, `refreshEnv`, `listProcesses`, `killProcess`,
`registryRead`, `registryWrite`, `wingetSearch`, `installExe`. Реестр: **1619 → 1340**, наружу
по-прежнему **159 имён в том же порядке** (ссылки `system.имя` на прежних местах — куски в реестре
несмежные: два блока в начале, `listProcesses`/`killProcess` в середине, реестр и установщик ближе к концу).

**Зависимости (24 имени, все — плоские `deps` из `system-stack.js`):** `path`, `fs`, `os`, `agentWorkDir`,
`runTerminalCommand`, `spawnRaw`, `installSystemPkg`, `downloadFileTo`, `verifyInstaller`, `installerFacts`,
`installerGate`, `findInstallersIn`, `downloadAndExtractTo`, `envPathInfo`, `findProgram`, `runProgVersion`,
`psScript`, `cachedPs`, `invalidatePsCache`, `refreshEnvFromOS`, `truncateText`, `parseProcessesCsv`,
`parseSysInfoJson`, `registryPathAllowed`. Живого моста не нужно: модуль собирается РОВНО с одним аргументом
(проверяется живым прогоном).

**Проверено:** рантайм-сверка — **159/159 тел байт в байт**, состав и порядок ключей те же; область
видимости модуля — 93 распознанных имени, ни одного вызова без объявления (строки и комментарии из
проверки вырезаны: иначе половина «вызовов» — это тексты подсказок вида «killProcess(pid или name)»
и параметры PowerShell); `npm test` — 64 набора, зелёный.

**Сторожа.** Модуль добавлен во все списки дома (`test/tool-registry.test.js`, три списка в
`test/smoke.test.js`, `scripts/live-tool-registry.js`). Две проверки про `installExe` были прибиты к
соседу в файле — переведены на `toolBodySelf` (см. ловушки в `HANDOFF` §4), иначе проверка падала пустотой.

**Живой прогон `npm run test:live:tools-system` — 41 ✅ / 0 ❌.** Поднимается настоящий `main.js`
(поддельный только электрон) и вызываются инструменты тем же путём, что у агента. По делу проверено:
визитка ЭТОЙ машины (ОС, версия Node, домашний каталог, рабочая директория агента, настоящий PATH — 8 записей,
версии git 2.34.1 и node, спрошенные у настоящих программ); список процессов — **свой процесс найден по PID**;
`killProcess` — отказ без аргументов, честное «уже завершён» для несуществующего PID и **настоящее завершение
подопытного процесса** (проверка `process.kill(pid, 0)` после); `installSystemPackage` — отказ без имени и
правда «git уже установлен» (без всякой установки); `refreshEnv` — настоящий PATH и сколько записей было/стало;
реестр и winget на Linux — честный отказ «только на Windows»; `installExe` — отказ без URL, отказ на не-http,
`.msi` отвергнут ДО загрузки (и файла действительно нет), неудачные загрузки `.exe`/`.zip` бьют в закрытый
порт localhost и объясняются, мусора не остаётся. **На этой машине ничего не устанавливалось и не менялось.**

**Контроли.** (1) Снять предохранитель `.msi` (`installerGate` → пустая строка) — ловит набор:
«решение о запуске не во всех ветках». (2) Заставить `killProcess` только ОТЧИТЫВАТЬСЯ об остановке —
набор не ловит вообще (0 падений), а живой прогон ловит дважды: «OK — процесс PID … завершён» и
«процесс действительно мёртв». Ради таких случаев живой прогон и писался. Файл возвращён, `sha256` совпал.
