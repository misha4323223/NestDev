## Часть 80: ключи доступа в карточке сервисного аккаунта — по существующему адресу

**Зачем.** Карточка сервисного аккаунта на «Статических ключах» показывала отказ
вместо списка: `404` на обе попытки — и по сервисному аккаунту, и по каталогу.
Причина не в правах и не в облаке: ресурса `/iam/v1/accessKeys` **не существует**.
Статические ключи живут только в AWS-совместимом API IAM (`AccessKey.List` —
`/iam/aws-compatibility/v1/accessKeys`), а параметра `folderId` у метода нет вовсе,
то есть «добрать по каталогу» было нельзя в принципе — вторая форма запроса не
могла сработать никогда и заслоняла собой настоящую причину.

Досаднее всего, что этот же ресурс уже был описан в проекте ПРАВИЛЬНО: модуль
агента `src/yc-iam.js` ходит по aws-совместимому адресу. Но у одного ресурса
оказалось два независимых описания пути, и ничто не требовало, чтобы они
совпадали, — поэтому консоль и агент отвечали на один вопрос по-разному.

**Что сделано.** В реестре связей консоли (`src/yc-console.js`) путь заменён на
`/iam/aws-compatibility/v1/accessKeys?serviceAccountId=…&pageSize=1000`, а вторая
форма с `folderId` убрана вместе с фильтром `parentField` — фильтровать больше
нечего, ответ и так про этот аккаунт. В подменённом облаке живого прогона
(`scripts/live-yc-console.js`) ответ перенесён на существующий адрес, а сценарий
«403 по аккаунту → добор по каталогу» заменён на честные проверки: ключи
прочитаны, и запрос ушёл именно на существующий адрес (по журналу запросов).
Соседние пункты карточки (API-ключи, ключи подписи) не трогались — их адреса
верны, ошибка была только здесь.

**Проверено.** Новый раздел [5] набора `test/yc-iam.test.js` (2 проверки). Первая:
в живом коде консоли нет несуществующего пути (поиск идёт по коду БЕЗ комментариев,
иначе запрет путался бы с пояснением), попытка ровно одна, путь начинается с
aws-совместимого адреса и не содержит `folderId`, у связи нет `parentField`; сам
разбор проверен двумя контролями. Вторая — живой запрос через подменённое облако:
`relationList` действительно читает ключ (ok, count 1, `YCAJEtest0001`, путь с
`aws-compatibility`), а прежний адрес получает **404** — то есть проверка не
«зелёная по построению». Плюс негативный контроль вживую: старый путь вернули в
консоль — оба стража покраснели с той самой ошибкой, которую видел человек
(«Не удалось прочитать «Статические ключи»»), фикс вернули — 33/0.
