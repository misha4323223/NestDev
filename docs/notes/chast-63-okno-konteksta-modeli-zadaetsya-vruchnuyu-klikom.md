## Часть 63: окно контекста модели — задаётся вручную, кликом по чипу «Контекст»

**Зачем.** На OpenAI-совместимых роутерах (nrouter.ai и подобных) окно модели НЕ сообщается: в ответе
`/models` нет ни `context_length`, ни `context_window`, ни `max_model_len`. Тогда `modelWindow` в
`provider-transport.js` возвращает 0, бюджет истории остаётся «на глаз» — `CLOUD_CTX_BUDGET = 400 000`
из `context-window.js`, — и на модели с настоящим окном 32k–128k история НЕ сжимается вовремя. Запрос
уходит за окно, и провайдер либо отказывает, либо молча обрезает начало — а в начале лежат схема
инструментов и системные правила. Отсюда видимая болезнь: агент «тупеет», перестаёт звать инструменты и
пишет код прямо в чат; новый чат «лечит» это на время. Авто-детект окна у OpenAI-совместимых провайдеров
принципиально невозможен (поля нет в спецификации), поэтому нужен ручной выбор.

**Что сделано.**
- Новый модуль окна `src/renderer/context-ui.js` (фабрика, как `reasoning.js`): чип заполняемости
  `#ctx-indicator` под полем ввода стал КНОПКОЙ (`role="button"`, `tabindex="0"`, Enter/Space) — по клику
  открывается попап `#ctx-popover` с пресетами («Авто»/32k/64k/128k/200k/1M) и строкой «Своё…»
  (`#ctx-pop-custom` + числовое поле `#ctx-pop-input` + «Применить»). Закрытие: повторный клик по чипу,
  клик мимо (mousedown), Escape. Значение хранится в `settings.contextWindow` (0 = Авто) и сохраняется
  обычным `persistSettings()`.
- Схема настроек (`src/settings-store.js`): `contextWindow: 0` в `DEFAULT_SETTINGS` и нормализация
  `Math.max(0, Math.min(8000000, Math.round(Number(s.contextWindow) || 0)))` — мусор и опечатки не уезжают
  в бюджет.
- Прогон (`src/run-ai.js`): ручное окно — ГЛАВНЕЕ авто-определения. После блока `modelWindow`/`windowBudget`
  читается `manualWindow = settings.contextWindow`: при `> 0` им подменяются `modelWin` и `budget`
  (`windowBudget(provider, manualWindow, manualWindow, { local })` — тем же расчётом, минус резерв на
  ответ), с полом `Math.min(3000, manualWindow)`. Потолком ставится САМО число, а не облачный бюджет:
  человек знает свою модель лучше нашей экономии.
- Разметка/стили: `src/renderer/index.html` (кнопка-чип + попап), `src/renderer/styles.css` (`.ctx-popover`,
  `.ctx-opt.active`, шестерёнка `.ctx-indicator.manual`). Оболочка `src/renderer/app.js` только собирает
  модуль (`window.ContextUI({...})`, `ContextUI.wire()`); телефон получает модуль (`STATIC_FILES` в
  `src/mobile-bridge.js`).
- Карта интерфейса `ARCHITECTURE.md` + потолок прямых чтений app.js в `test/repo-shape.test.js` (39 → 40) —
  как и положено новому модулю окна.

**Почему так, а не «таблица окон по имени модели».** Окно модели у OpenAI-совместимых API не отдаётся, а
угадывать по имени — гадание: у одного шлюза это полное окно, у другого обрезанное. Поэтому авто-определение
оставлено как есть (Ollama `/api/show`, поля в `/models` у тех, кто их отдаёт), а случай «окно не сообщается»
лечится явным выбором человека. «Авто» остаётся значением по умолчанию: там, где окно известно, трогать нечего.

**Грабли.** Метки пресетов и значения берём из САМОЙ разметки, а не из констант: `fmtWindow` сначала ищет
подпись среди кнопок (131072 → «128k»), и только для нестандартных чисел считает по 1000 — иначе
подтверждение «128k» показывало бы «131k» и сбивало с толку. Набор `test/context-ui.test.js` (15 проверок)
водит модуль на игрушечном окне из НАСТОЯЩИХ id разметки: набор вне цепочки — это не набор.
