## Часть 71: Cloud Functions видны, вызываются и выкатываются (`yc-functions.js`)

**Зачем.** Облако умело показать только контейнеры и базы. Cloud Functions — самый дешёвый способ получить
«что-то, что отвечает в интернете»: пока функцию не зовут, она не стоит ничего (первые 1 млн вызовов и
10 ГБ×час в месяц не тарифицируются), а для редкой задачи вроде вебхука или обработчика кнопки она дешевле
машины, которая платит за каждый час простоя. Агент про функции не знал ничего — ни посмотреть, что уже
развёрнуто, ни выкатить свой код.

**Что сделано.**
- `src/yc-functions.js` — модуль Cloud Functions (чистый Node, без Electron): список и карточка, обзор с
  недоделками, создание и правка функции, версии (создание, список, удаление), теги, вызов, публичность и
  привязки ролей. Плюс мелочи, которые делают инструмент пригодным для модели: проверка имени и тега по
  правилам сервиса, разбор памяти («512», «1 ГБ», байты) с приведением к шагу 128 МБ, разбор времени
  (30 / «30 с» / `PT30S`, максимум 600 с), живой список языков, карточка словами, объяснение кодов ответа.
- Ключевые решения, которые нельзя терять при правке:
  - **у функции НЕТ кода — код живёт в ВЕРСИИ**: «поменять функцию» значит создать версию, и вызов всегда
    попадает в какую-то версию;
  - **по умолчанию отвечает САМАЯ НОВАЯ версия** (виртуальный тег `$latest`), поэтому адрес без тега меняет
    поведение от каждой выкатки, а постоянную ссылку даёт ТОЛЬКО тег (`v1`, `prod`). Обзор считает
    «без постоянного тега» по БОЕВОЙ версии, а не по наличию тега где-нибудь на старье;
  - тело создания версии сверяется целиком: память уходит БАЙТАМИ строкой (`"536870912"`), время — строкой
    секунд (`"30s"`), тег — списком, а источник кода РОВНО один из трёх (`content` из файла-архива,
    `versionId` для копии прежней версии, `package { bucketName, objectName }` для архива в бакете);
  - язык проверяется по ЖИВОМУ списку `/functions/v1/runtimes`: придуманный «node20» отбивается понятным
    отказом с похожими вариантами, а не сырой английской ошибкой сервиса;
  - тег уникален: постановка тега на другую версию СНИМАЕТ его со старой, и об этом сказано словами («тот
    адрес теперь отвечает новым кодом»). «Уже стоит» и «снимать нечего» в облако не пишут;
  - **вызов идёт на публичный адрес функции**, а не в API сервиса, и его ответ — это ответ чужого кода: он
    может быть JSON, текстом или пустым (пустой — не ошибка, а 403 объясняется ролью
    `serverless.functions.invoker`, 504 — тем, что функция не успела, с отсылкой к логам);
  - **публичность — это роль `serverless.functions.invoker` на `allUsers`**, а не флаг: снимается и
    ставится дельтой `ADD`/`REMOVE`, и после записи привязки ПЕРЕЧИТЫВАЮТСЯ;
  - удаление функции забирает ВСЕ её версии и теги (и зовущие её триггеры), поэтому сначала называются
    уходящие версии, публичность и триггеры; удалить ПОСЛЕДНЮЮ версию нельзя вовсе — функция без версий не
    отвечает, и это прямо сказано в отказе;
  - права: выкатка (создание версии, создание функции) — `cloud.create`, теги/публичность/правка/удаление
    версии — `cloud.update`, удаление функции — `cloud.delete`; `confirm: true` нужен для удаления, а
    список языков отвечает даже без подключённого облака (он не про данные человека);
  - `zipFile` проверяется до запроса: файл должен существовать и начинаться с `PK`, иначе отказ с готовым
    рецептом (`Compress-Archive`), потому что «залил текстовый файл вместо архива» сервис встречает сырой
    ошибкой.
- **Три настоящие ошибки найдены и починены по ходу.** ① «30 с» не разбиралось: после `toUpperCase()`
  кириллическая «с» оставалась «С», а образец ждал латинские `S`/`SEC` — человек получал отказ на своём же
  формате из подсказки. ② «без постоянного тега» считалось по ВСЕМ тегам функции, поэтому тег на старой
  версии «прикрывал» боевую, которая всё равно поедет от следующей выкатки. ③ Разбор адреса вызова брал
  ХОСТ, а не id: `https://functions.yandexcloud.net/fn-1` искало функцию с именем
  «functions.yandexcloud.net» — по своему же адресу функция не находилась.
- **Попутная находка в роутере (важно для следующих блоков).** Каталог облака дорос до 10 435 токенов схем,
  и на окне 60k группа `cloud` перестала влезать: цена базы (6 948) + группа превысила ПОЛИТИЧЕСКИЙ потолок
  схем (`ROUTER_MAX_TOKENS` = 16 500), а «липкая» группа резалась им наравне с включённой по догадке — то
  есть на середине работы агент терял все облачные инструменты, а «Консоль» молчала. Теперь предел для уже
  включённых групп — только окно (`stickyMaxTokens`; `routerMaxTokens(budget, sys, base, { windowOnly: true })`),
  а потолок схем остался для групп, включённых догадкой (чтобы с ходу не набирать лишнего). Правка в ядре,
  `src/run-tools.js` и `src/renderer/web-chat.js`; поймал `test/run-tools.test.js` («справочник группы cloud
  не подключился»), он же это и стережёт.
- Набор `test/yc-functions.test.js` — **35 проверок** (в цепочке `npm test`): `[1]` единицы и правила без
  сети, `[2]` НАСТОЯЩИЙ модуль против локального HTTP-сервера с настоящей машиной состояний (хук
  `AI_AGENT_YC_BASE`) — тела создания функции и версии сверяются целиком, тег, публичность и удаление
  подтверждаются ПЕРЕЧИТЫВАНИЕМ, а негативные контроли «облако ответило „сделано“, а на деле ничего не
  изменилось» стоят на теге, публичности, правке и удалении; `[3]` инструмент агента `ycFunctions`
  (запреты звучат ДО запроса, удаление требует согласия, публичность предупреждает, ответ функции показан
  вместе с адресом); `[4]` проводка (канал `yc:functions`, мост, схема, группа «облако», промпт, права,
  справочник, сервис в дашборде и консоли, тип ресурса в логах, тариф).
- **Тариф Cloud Functions** в `src/yc-costs.js`: 6,48 ₽ за ГБ×час и 18,97 ₽ за миллион вызовов, бесплатно
  10 ГБ×час и 1 млн вызовов в месяц; расчёт собран из этих констант, а не из выдуманного числа, и на него
  ссылается「прайс」в самой оценке.

**Живая беда, которую эта часть закрывает.** Функции не были видны вовсе, поэтому на вопрос «что у меня
отвечает в интернете» агент мог ответить только «не знаю» — и человек шёл в чужую консоль.
