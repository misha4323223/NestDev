## Часть 81: `smoke.test.js` разложен по группам — 14 файлов вместо 19 257 строк в одном

**Зачем.** Часть 79 сделала файл читаемым сверху вниз (карта в шапке и бегунок в
конце), но он остался ОДНИМ файлом на 19 257 строк и 87 наборов: чтобы найти
нужную проверку, надо было помнить, что помощник с 16 744-й строки нужен набору на
1000-й. Разбор на части откладывался не из осторожности ради осторожности: тесты не
уезжают ни в установщик (`electron-builder.yml` кладёт `src/**`, `assets/**`,
`package.json`, `server.js`), ни в OTA-набор (`scripts/make-ota.js`, `INCLUDED` —
тот же список), поэтому ЕДИНСТВЕННЫЙ способ навредить продакшену — потерять
проверку при переносе. Значит, перенос обязан быть сверяемым машинно, а не «на глаз».

**Что сделано.** Разбор шёл этапами, каждый со своей проверкой.

1. **Помощники и состояние — `test/smoke/harness.js`.** 26 помощников (`hasTool`,
   `codeOnly`, `miniDom`, `fakeEl`, `panelDom`, `makeBundle`, `freePort`, `get`,
   `buildChatFeed`, `modelPrompt`, `uiFile`, `uiAll`, `uiFind`, `autoGuideNames` и
   прочие) переехали слово в слово вместе с состоянием модуля, без которого они не
   работают: `RENDERER_DIR`, `UI_ORDER`, `uiCache`, `otaSigner`, `OTA_TEST_KEYS`.
   Нужны только `fs/os/path/crypto/net/assert`.
2. **Проверки и итог — туда же.** `test()`, `selected()`, `ONLY`, счётчики
   `passed`/`failed` и новый `finish()` («Итог: N прошло, M упало», возвращает число
   упавших) уехали в `harness.js`, а точка входа оставила себе одну строку
   `process.exit(H.finish() ? 1 : 0);`.
3. **Текст всего набора — `test/smoke/source.js`.** Семь внешних читателей
   (`test/yc-billing`, `yc-cdn`, `yc-compute`, `yc-db`, `yc-registry`, `yc-storage`,
   `yc-ui`) читали `test/smoke.test.js` целиком; теперь они берут склеенный текст
   набора из `source.js`, а не знают, из скольких файлов он собран.
4. **Разбор карты — `test/smoke/map.js`.** Чтение файлов набора, строки карты,
   объявленные наборы и вызовы бегунка вынесены отдельно (`ROOT`, `SET_FILE`,
   `GROUP_DIR`, `setFiles`, `setSources`, `mapRows`, `declaredSuites`, `declaredAll`,
   `runnerCalls`, `lineAt`, `lastNonEmpty`, `mapProblems`); `harness.js` их только
   переиспользует.
5. **У карты появился столбец «файл»** — `| файл | строка | набор | что проверяет |`.
   `testSelfIndex` (по-прежнему 4 проверки) сверяет номера строк В ТОМ ФАЙЛЕ, который
   назван в карте, равенство строк карты и наборов по всем файлам и то, что бегунок
   зовёт каждый набор ровно один раз и стоит последним. Собирает карту
   `scripts/smoke-map.js` — `npm run smoke:map`, проверяет свежесть `--check`
   (он же понимает и старый формат карты).
6. **13 групп — своими файлами.** `01-chat`, `02-browser`, `03-cloud`, `04-deploy`,
   `05-mobile`, `06-agent`, `07-agent-tools`, `08-providers`, `09-ui`, `10-settings`,
   `11-ipc`, `12-misc`, `13-missions`: тело каждого набора перенесено БАЙТ В БАЙТ,
   порядок наборов и порядок вызовов не менялись (часть проверок пишет файл и читает
   его следующей — это часть логики). Точка входа сократилась с 19 257 до 562 строк:
   карта, девять имён из `harness.js`, тринадцать импортов групп, `testSelfIndex`,
   бегунок и `process.exit`.

**Ловушки, найденные по ходу (каждая закрыта насовсем).**

- **Наивная зачистка комментариев и строк ломается на регулярках с кавычками:**
  `/ipcMain.handle\("([^"]+)"\)/` разрезалась пополам, имена каналов терялись, и
  импорт выходил неполным (`ReferenceError: mainOnlySrc is not defined`). Заменено
  настоящим разбором кода (`codeOnly`: комментарии, строки, шаблоны, регулярка
  против деления по предыдущему значимому токену) плюс сверка баланса скобок.
- **`const skip = …` с нулевого столбца ВНУТРИ набора** ломал границы «до следующего
  объявления»: конец блока теперь — закрывающая `}` в нулевом столбце, а позицию
  реза ограничивает ещё и бегунок.
- **Переезд меняет смысл путей.** Перенос ОТКАЗЫВАЕТСЯ работать, если в уезжающем
  коде остались `__dirname` как путь или относительный `require`: пять
  `path.join(__dirname, "backend-wiring.js")` стали `path.join(ROOT, "test", …)`, а
  пять `require("../src/…")` — `require(path.join(ROOT, "src", …))`. Иначе группа
  искала бы файлы рядом с собой.
- **Наборы объявляют свои имена локально** (`const H = win.Highlight`,
  `const H = mkHelpers(...)`), и проверка «нет ссылок на невывезенное» считала это
  пропажей. Теперь локально объявленные имена исключаются, а ключ объекта
  `{ __dirname: "/app/src" }` не считается путём.

**Проверено.** `node test/smoke.test.js` — 543 проверки, 0 падений после каждого
этапа и в конце; фильтр по имени («карта файла» — 4/0) по-прежнему выбирает наборы.
`npm test` — 91 набор, exit 0. Негативные контроли вживую: сдвинуть номер строки в
карте (`test/smoke.test.js:999 — это не testDevRun`), назвать в карте чужой файл,
объявить набор в файле, которого нет в карте (`test/smoke/99-tmp.js :: testTmp`) —
все три покраснели и назвали расхождение; `--check` сообщает «новый набор». Откат
(`--undo`) применён трижды и каждый раз либо отказывал, либо возвращал файл как был.
`npm run test:boot` — «ЖИВОЙ ПРОГОН: всё чисто»; `test:live:cloud-panel` — 31 ✅,
`test:live:desktop` — 131 ✅ / 0 ❌ (один прогон дал 129/2 — эти проверки мигают,
код приложения не трогался). Живой прогон `test:live:yc` в песочнице красный и на
чистом коде (см. часть 80) — отдельная задача.

**Повторная проверка после сборки (тоже всеми способами).** Разбор сверили со
HEAD построчно: 87 наборов и 540 проверок совпадают, каждая строка групп есть в
HEAD (лишних ровно 104 — семь строк шапки и `const {` в каждом из тринадцати
файлов), а две новые утверждающие строки живут только в переписанном
`testSelfIndex` (столбец «файл» и контроль «набор в файле вне карты»); в
`map.js` новых `assert.` нет вовсе. Там же нашлись два дефекта самого
пересборщика, оба закрыты. Первый: номера строк в точке входа считались по
СТАРОЙ карте, поэтому при смене числа строк карты наборы ниже неё разъезжались
ровно на эту разницу — теперь сборка сходится за один проход (цикл до
стабилизации текста), а второй проход говорит «карта свежая». Второй:
`npm run smoke:map --check` до скрипта не доходил — npm забирал флаг себе и карта
молча пересобиралась; правильно `npm run smoke:map -- --check`, и это написано в
шапке скрипта и в HANDOFF. Живой негативный контроль на готовой раскладке:
набор в файле вне карты — сторож краснеет 2/2 и называет расхождение.
