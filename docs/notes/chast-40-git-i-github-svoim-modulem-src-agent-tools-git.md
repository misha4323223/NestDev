## Часть 40, заход 2: git и GitHub — своим модулем (src/agent-tools-git.js)

Шестнадцать обработчиков дома `agent-tools.js` уехали в свой модуль: `gitClone`,
`gitStatus`, `gitCommit`, `gitPush`, `gitPublish`, `gitInit`, `gitPull`, `gitLog`,
`gitRevert`, `gitBranch`, `gitCheckout`, `gitDiff`, `gitUndoLastCommit`, `gitStash`,
`gitCherryPick`, `gitBlame` — 212 строк. Реестр: 2495 → 2303 строки.

**Главное решение — ССЫЛКИ, А НЕ СПРЕД.** Девять облачных инструментов (заход 1)
лежали одним куском в конце реестра, поэтому там сработал `...createCloudTools(deps)`.
Эти шестнадцать идут ЧЕТЫРЬМЯ несмежными кусками (clone…revert, branch/checkout,
diff/undoLastCommit, stash/cherryPick/blame), и спред в конец переставил бы инструменты
в реестре. Поэтому на прежнем месте каждой записи стоит короткая ссылка
`"gitClone": git.gitClone,`, а тела живут в модуле. Порядок ключей сохранён ровно —
это отдельно проверено сверкой (состав И порядок против `HEAD`).

**Живой мост — вторым аргументом.** `gitClone` пишет папку последнего клона и поднимает
флаг «последний ответ — после клона»; это живые значения main.js. Модуль получает готовый
мост (`createGitTools(deps, live)`) и своей копии состояния не заводит. Сборка стоит
ПЕРЕД `return {` — иначе мёртвая зона (`live` объявлен выше; проверка на это добавлена
в сверку, как в заходе 5 части 39).

**Проверено.**
- Рантайм-сверка: модуль из `HEAD` и модуль с диска — **159/159 тел совпали байт в байт**,
  состав и ПОРЯДОК ключей те же; в реестре не осталось ни одного inline-тела git-инструмента,
  все 16 записей — ссылки, модуль собран до `return {`.
- Область видимости модуля: 12 распакованных имён, ни одного имени старого замыкания без
  внедрения, ни одного имени вне модуля и вне глобалов.
- `npm test` — **64 набора, 1333 проверки, 0 падений**.

**Сторожа.** `agent-tools-git.js` добавлен в те же три списка, что и `agent-tools-cloud.js`
(`backendSrc()` и два списка `scanWiring`); обратные проверки (`test/tool-registry.test.js`,
`scripts/live-tool-registry.js`) теперь берут распаковку у ВСЕХ модулей дома — список
`TOOLS_HOME` вместо одного `TOOLS_EXTRA_SRC`. Страж связи на новом модуле чист: 0 missing,
0 assigns, 0 bareLive.

**Находка про сам страж.** Помощник `bareCode` в `test/backend-wiring.js` вырезает
комментарии ДО строк, поэтому адрес вида `https://…` внутри строки уносит остаток строки
вместе с закрывающей кавычкой. Для `missing`-проверки это безвредно (имена сверяются с
топом main.js), но любая проверка «в файле есть чужое имя» на таком тексте даст мнимое
срабатывание — у меня так и вышло (GitLab/Bitbucket/personal access token). Свою сверку
я написал с правильным порядком (строки и шаблоны → регулярки → комментарии); трогать
общий помощник не стал, чтобы не менять поведение чужих проверок.
