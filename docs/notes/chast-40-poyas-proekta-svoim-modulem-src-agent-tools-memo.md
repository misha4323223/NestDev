**Зависимости (9 имён, все — плоские `deps`):** `fs`, `loadSettings`, `resolvePath`, `agentWorkDir`,
`app`, `agentStore`, `codeIndex`, `userDataDir`, `emitTasksChanged`. Живого моста не нужно: модуль собирается
РОВНО с одним аргументом (проверяется живым прогоном). Разбор зависимостей нашёл в телах слово `path` — это подсказка «readFileLines(path, start, count)» в тексте, а не вызов: распаковка `path` была бы мёртвой и убрана, поэтому имён девять, а не десять.

**Имя ссылки — `memory`:** в шапке `agent-tools.js` такого имени нет (дома data-модулей зовутся `agentStore`,
`missionStore`), поэтому ловушка захода 6a (`net` занято модулем node) не повторилась — но список распаковки
перед выбором имени всё равно просмотрен.

**Проверено:** рантайм-сверка — **159/159 тел байт в байт**, состав и порядок ключей те же; область видимости
модуля чистая (55 распознанных имён, необъявленных вызовов нет); `npm test` зелёный.

**Сторожа.** Модуль добавлен в оба списка дома (`test/tool-registry.test.js` — `TOOLS_HOME`, три списка в
`test/smoke.test.js`, список `scripts/live-tool-registry.js`). Но одной этой правки мало: проверка «повтор
доходит до хранилища» (`repeat: args.repeat`, `snooze: args.snooze`) читала ФАЙЛ-оболочку — после выноса
`taskAdd` она покраснела не смыслом, а отсутствием строки. Урок записан в `HANDOFF` §4 (второй вид ловушки
«сторож прибит к файлу»): там, где спрашивают про тело, дом читается ЦЕЛИКОМ — в smoke для этого появился
`toolsHomeSrc()`. Миссии и план (`missionOfRun`, `todoWrite`) пока живут в оболочке, и три проверки про них
ещё читают файл прямо — при заходе по миссиям их надо перевести на `toolsHomeSrc()`.

**Набор (поведенческий).** В `test/smoke.test.js` добавлена проверка «пояс проекта: заметки, дела, чекпоинты
и поиск по смыслу — на настоящем диске»: модуль берётся настоящий, хранилище настоящее (`src/agent-store.js`),
индекс настоящий (`src/code-index.js`), диск настоящий. Проверяется дело, а не текст: заметка с кириллическим
ключом сохраняется и читается по переведённому имени, файл памяти лежит в `userData`, а НЕ в проекте; повтор
и автозапуск видны списку; чекпоинт снимается, файл правится и откат возвращает ПРЕЖНЕЕ содержимое (чтение с
диска); поиск по смыслу находит настоящий исходник, а пустой запрос отвергается до поиска.

**Живой прогон `npm run test:live:tools-memory` — 52 ✅ / 0 ❌.** Поднимается настоящий `main.js`
(поддельный только электрон) и настоящий реестр; всё делается в своей временной папке. По делу: `noteSave`
с ключом «Клиенты ВК» → `klienty-vk`, память в `userData/project-memory`, в проекте её нет; `taskAdd` с
`repeat`/`auto` → список показывает «🔁 каждый день» и «▶ выполняет агент», `taskDone`/`taskDelete` не
выдумывают успех на удалённом деле; выключенная память диалогов честно объяснена, после включения галочки
памятка находится поиском; чекпоинт снят (4 файла), файл испорчен и откат вернул его содержимое, чекпоинт
виден в списке, несуществующий и негодный id отвергнуты по-разному; `semanticSearch` по «validateLogin»
нашёл «сервер.js» с самим кодом в ответе.

**Три неверные пробы (мои, не инструмента).** (1) «несуществующий чекпоинт» проверялся кириллическим id —
такой отвергается РАНЬШЕ поиска, проверкой формата; теперь два случая проверяются раздельно. (2) Запрос
поиска по смыслу «валидация входа» — индекс ищет по словам кода (auth → authenticate), русской формулировки
для английского имени в нём нет; проверяю обе границы: находит имя из кода и честно объясняет отсутствие
совпадений. (3) Требование «в проекте не осталось НИЧЕГО, кроме файла» — приложение держит там свою
служебную папку `.agent` (журналы и памятки); проверяю, что чужого мусора нет и что память с делами туда
не легли.

**Контроли.** (1) Откат чекпоинта, который только ОТЧИТЫВАЕТСЯ (не пишет файл), — ловит набор, и именно
проверкой на диске: «файл не вернулся к прежнему содержимому»; файл возвращён, sha256 совпал.
(2) Застывшая копия настроек в `memoryList` (`loadSettings()` один раз) — набор СЛЕП (его `loadSettings`
всегда отвечает «включено»), а живой прогон ловит: «дни названы» падает, потому что память осталась
выключенной. Файл возвращён, sha256 совпал. Ради таких случаев живой прогон и писался.
