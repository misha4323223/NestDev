## Часть 47: файлы бакета Object Storage — посмотреть, положить, забрать и убрать

**Задача (просьба человека).** Продолжение той же темы «облако руками агента»: бакет
создавался «для файлов и статики» (`ycCreate { service: "storage" }`, список — `ycList`), но
положить в него файл было нечем — созданный ресурс оставался пустой полкой: ни выложить
статику, ни отдать файл. Та же болезнь, что у секрета без версии и зоны без записи (часть 46).

**Что сделано — инструмент агента `ycStorage`** (`src/agent-tools-cloud.js`, дома стало
**13** обработчиков: девять + три части 46 + этот):

- `list` (что лежит в бакете; `prefix` — «папка», `limit`), `upload` (файл с ПК — `file`,
  либо готовый текст — `content`, либо `contentType` вручную), `download` (забрать объект
  к себе — `to`, по умолчанию имя объекта в рабочей папке), `delete` (убрать объект).
- `bucket` — имя или id; без него работает, только если бакет в каталоге один. `key` — путь
  объекта (ведущие слэши срезаются), `file` — путь от рабочей папки; файл больше
  `S3_MAX_BYTES` (64 МБ) отклоняется ДО сети, как и пустой ключ.
- Разрешения названы так же, как у остальных ресурсов, и стоят ДО всякой сети: `upload`
  требует «Разрешить агенту создавать ресурсы», `delete` — «…удалять ресурсы».
- Ответы ведут человека дальше: подсказка, чем создать бакет, «что осталось» после удаления и
  адрес объекта — **с честной оговоркой**, что открывается он у других, только если у бакета
  включён публичный доступ на чтение (обещать рабочую ссылку без этого нельзя). Именно эту
  оговорку и закрыла часть 49.

**Служебный слой (`src/yandex-cloud.js`).** Объекты живут НЕ в консольном API каталога
(storage-api), а в S3-совместимом (`storage.yandexcloud.net`), и у него два отличия, которые
легко потерять при правке: ответы — **XML** (JSON-варианта нет), причём с экранированием
(`&amp;` в ключе — это имя файла пользователя), а авторизация идёт IAM-токеном **без подписи
запроса** (`Authorization: Bearer <IAM>`), поэтому ни статический ключ, ни подпись
AWS4-HMAC-SHA256 не нужны. Тип содержимого берётся из расширения ключа (`contentTypeFor`),
открытый адрес собирается без двойных слэшей (`objectPublicUrl`). Если кто-то «упростит»
запрос до JSON или добавит подпись — набор обязан покраснеть.

**Каналы и окно.** Новый канал `yc:console:storageObject` (19 → 20), проброс в `preload.js`,
запрет телефону в `mobile-bridge.js` (файлы платного хранилища убираются с ПК). В карточке
бакета — связь «Объекты» (`storage:objects`, читается из S3), а удаление — прямо из таблицы,
**с подтверждением панели**, а не с одного клика (та же проводка `confirmModal`, что у образа
реестра).

**Ловушка 15 подтверждена ещё раз, с уточнением порога.** Правка не видит содержимое файла
дальше ~32–36 КБ: в `src/agent-tools-cloud.js` (54 КБ) якорь на строке 528 не нашёлся вовсе,
тогда как `test/repo-shape.test.js` (31 КБ) и `src/yc-console.js` (37 КБ, строка 710)
правятся штатно. Поэтому второй контроль взят по тому же решению с другой стороны (обёртка
панели), а не «насильно» через скрипт: временная порча и возврат через скрипт оставляют след
в состоянии синхронизации.
