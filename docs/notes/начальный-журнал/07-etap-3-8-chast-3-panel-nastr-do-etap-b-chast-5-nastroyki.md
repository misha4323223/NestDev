### Две настоящие поломки, которые нашёл живой прогон окна

Зависимости проводки вычисляются **на загрузке окна**, а модули объявляются `const`.
Два места читали модуль, объявленный ниже, и роняли загрузку целиком:

1. проводка OpenAI-подключений (выше секции настроек) читала `SettingsPanel.setSettingsMsg` —

`getYcPanel: () => YcPanel`). Симптом был бы тот самый, из-за которого человек уже
приходил с «в чате пусто»: окно живо, а весь остаток загрузки (включая подписку на
события агента) не выполняется.

### Новый сторож: проводка не читает модуль, объявленный ниже

`repo-shape`: для каждого блока `const X = window.X({ ... })` проверяется, что ни одна
строка блока (кроме комментариев и отложенных стрелок) не берёт биндинг модуля,
объявленного ниже. Проверено негативным контролем — и он сразу показал, что первая
версия сторожа была **наивной**: она искала только `Модуль.метод`, а настоящая поломка
выглядела как `YcPanel: YcPanel` (прямое чтение значения). Вторая версия ловит оба вида,
пропускает ключи объектов и строку самого объявления.

## 1.5.140 — адрес превью для телефона сохраняет порт проекта

Ошибка, найденная при выносе правой панели и тогда осознанно не тронутая.

**Что происходило.** В `previewOpen` (теперь `side-panel.js`) адрес для телефона собирался
подстановкой `window.mobileApi.host` — а это `location.host` моста, то есть `IP:9090`.
Регулярка съедала вместе с `localhost` **и порт проекта**: `http://localhost:5000`
превращался в `http://192.168.1.72:9090`. Мост слушает 9090 и отдаёт файлы **самого окна**
(прокси к dev-серверу в `mobile-bridge.js` нет — проверено), поэтому в превью на телефоне
открывалось приложение вместо сайта проекта. Правка: подменяем **только хост**, порт берём
из адреса проекта — `http://192.168.1.72:5000`.

**Правка одна строка** (`src/renderer/side-panel.js`), плюс переписан тест, который это
поведение **закреплял**: проверка в `smoke` ожидала `http://192.168.1.5:9090/app` с
комментарием «подмена — как была… в выносе поведение не тронуто». Теперь проверок четыре:
порт проекта сохраняется (3000), порт по умолчанию 5000 сохраняется, `127.0.0.1` тоже
подменяется, а чужой адрес (`https://example.com/app`) **не** подменяется; отдельно —
что в настройки уезжает адрес проекта, а не адрес для телефона.

### Ни одной подстановки

**262 строки перенесены байт в байт — отличий ноль, ни одной подстановки.** Это первый
вынос, которому вообще не понадобился мост: хранилище не держит живого состояния, оно
работает с файлами. Наружу приходит `app` (в тестах путь подставной) и три значения из
оболочки: `applyAgentEnv`, `applyBrowserSettings`, `audit` — применение настроек к живым
подсистемам осталось в `main.js`, а не уехало в хранилище.

### Имена не переименовывались вообще

Сборка модуля стоит на прежнем месте куска, и оболочка берёт те же функции
деструктуризацией:

```js
const { DEFAULT_SETTINGS, normalizeSettings, loadSettings, saveSettings, loadChats, saveChats,
  openaiProfilesList, switchOpenaiProfile } = createSettingsStore({ … });
```

Поэтому 26 вызовов `loadSettings()` и вся проводка в другие модули остались дословно
прежними — диф по `main.js` это только удалённый кусок и вставленная сборка. Такой путь
выбран осознанно: переименование 35 вызовов в файле на 4500 строк — это 35 шансов
ошибиться там, где ничего менять не нужно.

### Ловушка: тесты, которые читали схему настроек в `main.js`

Пять проверок в `smoke.test.js` искали значения по умолчанию прямо в оболочке
(`taskAuto: true`, `longWorkHours: 8`, `agentWorkFiles: true`, `mobileHost: "192.168.1.72"`)
и падали на выносе — хотя поведение не менялось. Правило из `ARCHITECTURE.md` («проверка
"функция X есть в main.js" при выносе X в модуль должна смотреть в модуль») пришлось
применить к схеме настроек: теперь они читают `src/settings-store.js`. Заодно вынес хранение
чатов в тесте чатов — из модуля, настоящим кодом, а не копией.
