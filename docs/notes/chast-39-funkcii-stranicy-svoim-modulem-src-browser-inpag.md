## Часть 39, заход 1: функции страницы — своим модулем (src/browser-inpage.js)

`src/browser-tools.js` (3566 строк) — самый крупный дом бэкенда, и разбирать его целиком опасно:
у него полтора десятка общих переменных модуля (браузер, вкладки, контекст CDP, режим), которые
сессия и инструменты делят между собой. Поэтому начали с САМОГО безопасного шва — функций, которые
исполняются ВНУТРИ страницы.

**Почему этот шов безопасен по построению.** Их передают в `page.evaluate` ПО ССЫЛКЕ
(`page.evaluate(scrollStateInPage, …)`) или вклеивают через `.toString()` (`evalValueToPlain`).
Playwright шлёт в страницу ТОЛЬКО исходник такой функции, значит она уже ничего не берёт из замыкания
модуля — только `window`/`document` и свои аргументы. Перенос не меняет ни одной связки, только
место объявления. Семнадцать функций (~570 строк) уехали в `src/browser-inpage.js`;
`browser-tools.js`: **3566 → 2984**, и он их реэкспортирует — наружу API не изменился ни на имя.

**Замечание к переносу (страховка).** `varValueInPage` зовёт `evalValueToPlain`, и обе уезжают в
страницу — поэтому они обязаны жить в одном файле, и в шапке модуля это сказано прямо, чтобы их не
разнесли.

**Перенос байт в байт.** Скрипт-переносчик режет по якорям (объявление функции → первая строка `}`
на нулевом отступе); функция едет вместе со своим комментарием, пустая строка-разделитель не едет, а
секционный заголовок `// ── …` остаётся в `browser-tools.js` (он про РАЗДЕЛ, а не про одну функцию).

**Сверка ДО и ПОСЛЕ — по исходнику, а не «похоже».** Временный сверочный прогон берёт прежний
`browser-tools.js` из `git show HEAD` и сравнивает с собранным: состав экспорта (64 имени), тип
каждого и `fn.toString()` каждой функции. Итог: **64/64 функции совпали байт в байт**, 17 вынесенных
сверены и с `browser-tools`, и с `browser-inpage`, и с версией ДО.

**Проверки.** `npm test` — 64 набора, 1333 проверки, 0 падений. Наборы, которые зовут вынесенные
функции напрямую (`collectInPage`, `cleanupInPage`, `itemsKeyInPage`, `scrollStateInPage`,
`unwrapEvalValue`/`evalValueToPlain`/`varValueInPage`/`describeVar`), берут их через
`browser-tools` как и раньше. Живые: `test:boot` — чисто; `test:live:browser` — чисто.

**Негативный контроль** (файл восстановлен байт в байт, `sha256` тот же — `ead4bc93…`): в
`unwrapEvalValue` вернул обёртку вместо значения (`return value` вместо `return value.v`).
Покраснело и там, и там: сверка — «исходник unwrapEvalValue изменился» и «не совпал с версией ДО»
(2 расхождения); набор — падение «browserEval: DOM-узел, объект с циклами и undefined объясняются».

**Ловушка инструментов (стоила времени).** Новый файл, созданный скриптом, файловый инструмент НЕ
видит (`str_replace` отвечает «файла нет»), хотя Node его читает; пока файл не заведён через файловый
инструмент, правки в нём могут не попасть в синхронизируемое состояние сборки. Поэтому
`browser-inpage.js` заведён через файловый инструмент, и первым делом сверены `sha256` до и после
(совпали).

CDP) остаётся ядром `browser-tools.js`.
